# Context Handoff Skill (세션 맥락 인계 스킬)

본 스킬은 컨텍스트 창 압축, 세션 재시작, 또는 다른 에이전트/개발자에게 장기 작업을 인계할 때 작업 손실 없이 맥락을 복구하는 절차를 안내합니다. 짧은 단일 세션 작업에는 별도 문서를 만들지 않으며, 프로젝트에 기존 상태·인계 문서 규약이 있으면 이를 우선합니다.

---

## 🎯 사용 시점

- **세션 압축 / 리셋 직전**: 대화 컨텍스트가 가득 차서 `/clear` 또는 새로운 세션을 시작해야 할 때
- **긴급 작업 인계**: 다른 에이전트나 사용자에게 현재까지의 시도와 남은 과제를 전달할 때
- **복잡한 장시간 작업**: 여러 단계로 구성된 작업을 진행하며 중간 이정표를 기록해야 할 때

---

## 📋 핸드오프 문서 표준 포맷 (`HANDOFF.md`)

작업 공간 루트 또는 지정된 폴더에 `HANDOFF.md` 파일(또는 요청받은 위치)을 생성하거나 수술적으로 업데이트하십시오.

```markdown
# 🤝 Task Handoff Document

- **최종 업데이트 시각**: YYYY-MM-DD HH:MM:SS
- **담당 작업 / 목표**: [수행 중이던 목표 간략 기술]
- **완료 기준**: [작업이 끝났다고 판단할 수 있는 검증 가능한 조건]

---

## 📌 현재 진행 상황 (Current Progress)

- [x] [완료된 작업 1]
- [x] [완료된 작업 2]
- [ ] [진행 중 / 미완료 작업 3]

---

- [성공적인 구현 방식, 통과한 테스트, 유효했던 전략]

### ❌ 실패한 접근법 및 주의사항 (What Didn't Work)
- [실패했던 원인, 발생했던 에러 로그, 시도했으나 차단된 경로]

- **실행한 검증**: [명령, 테스트 또는 수동 확인과 결과]
- **미검증 범위 / 이유**: [실행하지 못한 항목과 이유]
- **보류한 위험 또는 결정**: [다음 세션이 알아야 할 제약]

## 🚀 다음 세션 액션 플랜 (Next Steps)

1. [다음 세션 에이전트가 가장 먼저 시작해야 할 작업]
2. [검증해야 할 항목]
3. [주의해야 할 엣지 케이스]
```

---

## 💡 에이전트 실행 지침

1. `/handoff` 지시를 받거나 장기 작업의 세션 전환이 필요하다고 판단되면 현 시점의 작업 상태를 정밀하게 분석합니다.
2. 프로젝트에 기존 상태 문서가 있으면 해당 규약을 우선합니다. 별도 문서가 필요할 때만 `HANDOFF.md`를 생성하며, 이미 존재하면 기존 내용을 파괴하지 않고 수술적 편집(Surgical Edit)으로 업데이트합니다.
3. 생성 완료 후 새 세션에서 다음 한 줄 지시만으로 맥락을 복구할 수 있도록 사용자에게 안내합니다:
   ```text
   HANDOFF.md 읽고 이전 작업을 이어서 완료해줘.
   ```
