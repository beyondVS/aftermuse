# 기능 사양: 알라딘 Metadata Provider Adapter

**기능 브랜치**: `feature/day-02-auth-book-search`

**생성일**: 2026-09-03

**상태**: 초안

**입력**: 사용자 설명: "IMP-021 — 선행 작업 IMP-003을 기반으로 알라딘 검색 Adapter를 구현하되 외부 호출은 테스트에서 대체 가능하게 하며, 정상·실패·timeout 응답을 구분한다."

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 알라딘 도서 Metadata 검색 (우선순위: P1)

도서 검색 기능은 검색어를 알라딘에 전달하고, 후속 검색 흐름이 특정 Provider의 응답
형식에 의존하지 않고 사용할 수 있는 도서 Metadata 결과를 받는다.

**우선순위가 높은 이유**: 정상 검색 결과가 없으면 사용자가 책을 찾고 선택하는 Day 02
핵심 흐름을 진행할 수 없다.

**독립 테스트**: 준비된 정상 검색 응답을 사용해 검색을 실행하고, 각 도서의 식별자와
서지정보가 원래 의미를 유지한 결과로 반환되는지 확인할 수 있다.

**인수 시나리오**:

1. **Given** 유효한 검색어와 한 건 이상의 정상 도서 응답이 준비되어 있고, **When** 도서 Metadata를 검색하면, **Then** 각 도서의 ISBN13, 제목 및 제공된 선택 서지정보가 손실 없이 반환된다.
2. **Given** 유효한 검색어와 결과가 없는 정상 응답이 준비되어 있고, **When** 도서 Metadata를 검색하면, **Then** 실패가 아닌 빈 검색 결과가 반환된다.
3. **Given** 응답 항목에 ISBN13 또는 제목이 없고 다른 유효한 항목도 함께 있으며, **When** 응답을 처리하면, **Then** 불완전한 항목만 제외되고 유효한 항목은 반환된다.

---

### 사용자 스토리 2 - Provider 실패 식별 (우선순위: P1)

도서 검색 기능은 Provider가 요청을 처리하지 못했거나 응답을 해석할 수 없을 때 이를
정상 또는 빈 결과로 오인하지 않고 실패로 식별한다.

**우선순위가 높은 이유**: Provider 장애를 빈 결과로 표시하면 사용자는 실제로 책이
없는 것으로 오해하고 후속 흐름을 중단할 수 있다.

**독립 테스트**: Provider 오류, 통신 실패, 잘못된 응답 및 설정 누락을 각각 재현해
모두 실패로 분류되며 정상이나 timeout으로 분류되지 않는지 확인할 수 있다.

**인수 시나리오**:

1. **Given** Provider가 명시적인 오류를 반환하거나 통신에 실패하고, **When** 검색을 실행하면, **Then** Provider 실패 결과가 반환된다.
2. **Given** 응답이 손상되었거나 기대한 검색 결과 구조가 아니고, **When** 응답을 처리하면, **Then** 해석할 수 없는 응답 실패로 식별된다.
3. **Given** 검색에 필요한 Provider 설정이 준비되지 않았고, **When** 검색을 실행하면, **Then** 외부 요청 없이 설정 실패로 식별된다.

---

### 사용자 스토리 3 - Timeout 식별 (우선순위: P1)

도서 검색 기능은 Provider가 정해진 대기시간 안에 응답하지 않으면 일반 실패와 구분되는
timeout 결과를 제공한다.

**우선순위가 높은 이유**: timeout을 별도로 구분해야 후속 검색 흐름이 재시도 안내나
일시적 지연 메시지를 정확하게 결정할 수 있다.

**독립 테스트**: 대기시간 초과를 재현해 timeout으로만 분류되고 정상, 빈 결과 또는 일반
Provider 실패로 분류되지 않는지 확인할 수 있다.

**인수 시나리오**:

1. **Given** Provider가 허용된 대기시간 안에 응답하지 않고, **When** 검색을 실행하면, **Then** timeout 결과가 반환된다.
2. **Given** 일반 통신 실패와 대기시간 초과를 각각 재현하고, **When** 두 결과를 비교하면, **Then** 서로 다른 실패 유형으로 구분된다.

---

### 사용자 스토리 4 - 외부 호출 없는 계약 검증 (우선순위: P2)

개발자는 실제 알라딘 서비스의 상태나 자격 증명에 의존하지 않고 정상, 실패 및 timeout
조건을 대체 입력으로 재현해 연동 계약을 검증할 수 있다.

**우선순위가 높은 이유**: 외부 서비스에 의존하는 검증은 느리고 불안정하며 실패 유형을
원하는 시점에 재현하기 어렵다.

**독립 테스트**: 외부 호출 경계를 대체한 상태에서 정상, 빈 결과, Provider 실패, 잘못된
응답 및 timeout을 각각 재현하고 실제 알라딘 요청이 발생하지 않았는지 확인할 수 있다.

**인수 시나리오**:

1. **Given** 외부 호출을 대체하는 응답 공급자가 준비되어 있고, **When** 자동 검증을 실행하면, **Then** 실제 알라딘 요청 없이 모든 결과 유형을 재현할 수 있다.
2. **Given** 대체 응답 공급자가 요청 정보와 대기시간을 기록하고, **When** 검색을 실행하면, **Then** 검색어와 제한시간이 외부 호출 경계에 전달됐는지 확인할 수 있다.

### 예외 상황

- 검색 결과가 비어 있으면 실패가 아니라 정상적인 빈 결과로 처리한다.
- Provider가 성공 형태의 응답 안에 오류 정보를 포함하면 Provider 실패로 처리한다.
- 전체 응답을 해석할 수 없으면 부분 결과를 추측해 만들지 않고 응답 실패로 처리한다.
- 개별 항목의 ISBN13 또는 제목이 없거나 유효하지 않으면 그 항목을 결과에서 제외한다.
- 저자, 출판사, 출간일, 표지 위치, 소개 또는 목차가 없거나 해석할 수 없으면 해당 값을
  빈 값 또는 미상으로 보존하고 나머지 항목은 반환한다.
- 같은 검색어가 반복되어도 이번 기능은 결과를 저장하거나 캐시하지 않는다.
- Provider 자격 증명이나 민감한 요청 정보는 오류 결과에 포함하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 검색어를 사용해 알라딘 도서 Metadata 검색을 요청할 수 있어야 한다.
- **FR-002**: 시스템은 Provider 고유 응답을 후속 도서 검색 흐름이 사용할 수 있는 일관된 도서 결과로 변환해야 한다.
- **FR-003**: 각 도서 결과는 ISBN13과 제목을 필수로 포함하고, 제공된 저자 표시, 출판사, 출간일, 표지 위치, 소개, 목차 및 원본 도서 위치를 보존해야 한다.
- **FR-004**: 시스템은 결과가 없는 정상 응답을 실패와 구분되는 빈 결과로 반환해야 한다.
- **FR-005**: 시스템은 ISBN13 또는 제목이 없거나 유효하지 않은 개별 항목을 결과에서 제외해야 한다.
- **FR-006**: 시스템은 제공되지 않았거나 해석할 수 없는 선택 Metadata를 추측하지 않고 빈 값 또는 미상으로 반환해야 한다.
- **FR-007**: 시스템은 Provider가 보고한 오류와 통신 불가를 정상 결과와 구분되는 Provider 실패로 반환해야 한다.
- **FR-008**: 시스템은 손상되었거나 기대 구조와 다른 응답을 정상 결과와 구분되는 응답 실패로 반환해야 한다.
- **FR-009**: 시스템은 허용된 대기시간을 초과한 요청을 다른 Provider 실패와 구분되는 timeout으로 반환해야 한다.
- **FR-010**: 시스템은 필수 Provider 설정이 없으면 외부 요청을 시도하지 않고 설정 실패를 반환해야 한다.
- **FR-011**: 외부 호출 경계는 대체 가능해야 하며 정상, 빈 결과, Provider 실패, 잘못된 응답 및 timeout을 실제 알라딘 호출 없이 재현할 수 있어야 한다.
- **FR-012**: 시스템은 외부 호출에 적용할 최대 대기시간을 명시하고 그 값을 호출 경계에 전달해야 한다.
- **FR-013**: 실패 결과는 정상, 빈 결과 및 timeout과 서로 혼동되지 않도록 안정적으로 구분되어야 한다.
- **FR-014**: 시스템은 검색만으로 Book을 저장하거나 기존 Book Metadata를 변경해서는 안 된다.
- **FR-015**: 시스템은 Provider 자격 증명이나 민감한 요청 정보를 반환값 또는 오류 내용에 노출해서는 안 된다.
- **FR-016**: 이 기능의 자동 검증은 IMP-003의 품질 명령 환경을 사용하고 실제 알라딘 서비스에 요청을 보내서는 안 된다.

### 핵심 엔터티

- **도서 Metadata 검색 요청**: 사용자가 찾으려는 책을 나타내는 검색어와 허용 대기시간을 가진다.
- **Provider 도서 결과**: ISBN13과 제목을 필수로 가지며, 저자 표시, 출판사, 출간일, 표지 위치, 소개, 목차 및 원본 도서 위치를 선택 정보로 가진다.
- **Provider 처리 결과**: 정상 결과, Provider 실패, 응답 실패, 설정 실패 또는 timeout 중 하나로 식별되며 서로 중복되지 않는다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 모든 서지정보가 포함된 정상 응답 검증에서 반환된 도서의 필수·선택 Metadata가 100% 원래 의미대로 보존된다.
- **SC-002**: 정상 빈 응답 검증의 100%가 실패가 아닌 빈 결과로 식별된다.
- **SC-003**: Provider 오류, 통신 실패, 잘못된 응답, 설정 누락 및 timeout 검증의 100%가 지정된 결과 유형으로 분류되며 다른 유형과 중복되지 않는다.
- **SC-004**: timeout 검증의 100%가 일반 Provider 실패와 구분된다.
- **SC-005**: 실제 알라딘 외부 호출 0건으로 정상, 빈 결과, Provider 실패, 잘못된 응답 및 timeout의 자동 검증을 모두 완료할 수 있다.
- **SC-006**: ISBN13 또는 제목이 없는 항목이 포함된 응답 검증에서 잘못된 항목 반환은 0건이고 함께 제공된 유효 항목 손실도 0건이다.
- **SC-007**: 선택 Metadata가 누락된 정상 항목 검증에서 누락값 때문에 전체 검색이 실패하는 경우와 추측된 값이 생성되는 경우가 모두 0건이다.
- **SC-008**: 검색 검증 중 Book 생성 또는 기존 Book 변경은 0건이다.

## 가정

- 선행 작업 IMP-003의 테스트 및 품질 명령 구성이 완료되어 있다.
- 유효한 검색어의 길이, 빈 검색어 처리 및 사용자 입력 정규화는 후속 도서 검색 Service의 책임이다.
- 알라딘은 한국 도서 Metadata의 우선 Provider이며, Provider 이용 권한과 유효한 자격 증명은 운영 환경에서 별도로 준비된다.
- 자동 검증은 외부 호출 경계를 대체하므로 알라딘 서비스 상태, 네트워크 및 실제 자격 증명에 의존하지 않는다.
- 재시도, rate limit 대응, circuit breaker, 응답 캐시 및 검색 결과 저장은 이번 기능의 범위가 아니다.
- Provider 결과를 화면용 검색 결과로 정규화하는 정책은 IMP-022, 검색 화면은 IMP-023, Book 저장과 기존 Book 재사용은 IMP-024에서 다룬다.
