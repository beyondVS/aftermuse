## Clarifications

### Session 2026-09-07

- Q: 같은 책의 완독 Reading만 존재할 때, 새 재독 Reading은 언제 생성해야 합니까? → A: 완독 Reading을 먼저 보여주고, 사용자가 `다시 읽기`를 선택할 때 새 Reading을 생성한다.
- Q: 사용자가 Reading을 `완독`으로 변경할 때 완독일은 어떻게 정해야 합니까? → A: 오늘을 기본값으로 제시하고 사용자가 완독일을 선택하거나 수정할 수 있다.
- Q: 선택한 Book에 Reading이 전혀 없을 때, 사용자는 어떤 방식으로 첫 Reading을 생성해야 합니까? → A: `읽고 싶음`, `읽는 중`, `완독` 중 하나를 선택할 때 해당 상태로 Reading을 생성한다.
- Q: AI Interview가 시작된 뒤에도 사용자가 Reading의 완독일을 수정할 수 있어야 합니까? → A: Interview 시작 후에는 완독일을 수정할 수 없다.
- Q: 사용자가 `다시 읽기`를 선택할 때 새 재독 Reading의 초기 상태는 어떻게 정해야 합니까? → A: `다시 읽기` 후 `읽고 싶음`, `읽는 중`, `완독` 중 초기 상태를 선택한다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 선택한 책으로 Reading 시작 또는 계속하기 (우선순위: P1)

로그인한 사용자는 선택한 책을 자신의 한 번의 독서 경험인 Reading으로 만들고, 이미 같은
책에 진행 중인 Reading이 있다면 중복 생성 없이 그 기록을 계속 볼 수 있다.

**우선순위가 높은 이유**: Reading은 책 선택과 완독 후 AI Interview를 연결하는 핵심
기록이다. 이 흐름이 없으면 사용자는 선택한 책의 독서 상태를 관리하거나 다음 단계로
진행할 수 없다.

**독립 테스트**: 신규 Book을 선택해 Reading 화면에 진입했을 때 Reading이 생성되지 않았음을
확인하고, 상태를 선택한 뒤 정확히 한 건이 생성되는지 확인한다. 같은 Book을 다시 선택하면
동일한 활성 Reading이 열리고 추가 Reading은 생성되지 않아야 한다.

**인수 시나리오**:

1. **Given** 로그인한 사용자에게 선택한 Book의 Reading이 없고, **When** Book 화면에서
   `읽고 싶음`, `읽는 중`, `완독` 중 하나를 선택하면, **Then** 선택한 상태의 Reading 한
   건이 생성되고 그 Reading 상세 화면으로 이동한다.
2. **Given** 로그인한 사용자에게 같은 Book의 `읽고 싶음` 또는 `읽는 중` Reading이 있고,
   **When** 같은 Book에서 Reading 흐름을 다시 시작하면, **Then** 새 Reading을 만들지 않고
   기존 활성 Reading 상세 화면을 연다.
3. **Given** 서로 다른 두 사용자가 같은 Book을 선택했고, **When** 각자 Reading 흐름을
   시작하면, **Then** 각 사용자는 자신에게 속한 별도의 Reading을 갖는다.
4. **Given** 같은 사용자가 같은 Book의 독서 상태 선택을 짧은 간격으로 반복하고,
   **When** 요청 처리가 끝나면, **Then** 활성 Reading은 최대 한 건이고 모든 성공 결과는
   그 Reading을 연다.
5. **Given** 같은 Book에 완독된 Reading만 있고, **When** 사용자가 그 Book을 다시
   선택하면, **Then** 최근 완독 Reading을 먼저 보여주고 `다시 읽기`를 명시적으로 선택하기
   전에는 새 Reading을 생성하지 않는다.
6. **Given** 사용자가 완독 Reading에서 `다시 읽기`를 선택했고 같은 Book의 활성 Reading이
   없으며, **When** `읽고 싶음`, `읽는 중`, `완독` 중 초기 상태를 선택하면, **Then** 기존
   완독 Reading을 보존하고 선택한 상태의 새 Reading 상세 화면을 연다.
7. **Given** 사용자가 재독의 초기 상태로 `완독`을 선택했고, **When** 오늘 또는 과거의
   유효한 완독일을 확인하면, **Then** 선택한 완독일과 함께 별도의 완독 Reading이 생성된다.

---

### 사용자 스토리 2 - 독서 상태 및 완독일 관리 (우선순위: P1)

로그인한 사용자는 Reading을 `읽고 싶음`, `읽는 중`, `완독` 중 현재 경험에 맞는 상태로
바꾸고, 완독 상태와 완독일을 일관되게 관리할 수 있다.

**우선순위가 높은 이유**: 완독 여부는 AI Interview 진입 가능성을 결정하며, 잘못된 상태나
완독일은 사용자의 독서 이력과 후속 Reflection Context를 훼손한다.

**독립 테스트**: 하나의 Reading을 세 상태 사이에서 순서 제한 없이 변경하고, 완독 진입과
취소 때 상태와 완독일이 함께 올바르게 저장되는지 확인한다.

**인수 시나리오**:

1. **Given** 사용자가 자신의 Reading 상세 화면에 있고, **When** 현재와 다른 독서 상태를
   선택하면, **Then** 선택한 상태가 저장되고 화면에 즉시 현재 상태로 표시된다.
2. **Given** Reading이 `읽고 싶음` 또는 `읽는 중`이고, **When** 사용자가 `완독`으로
   변경하면, **Then** 오늘이 기본 완독일로 제시되고 사용자가 선택한 유효한 날짜와 함께
   완독 상태가 저장된다.
3. **Given** Interview가 시작되지 않은 완독 Reading이고, **When** 사용자가 `읽고 싶음`
   또는 `읽는 중`으로 되돌리면, **Then** 상태 변경이 저장되고 기존 완독일은 제거된다.
4. **Given** 사용자가 이미 읽은 책을 처음 등록했고, **When** 중간 상태를 거치지 않고
   바로 `완독`을 선택하면, **Then** 순차 상태 전이를 요구하지 않고 완독 처리가 완료된다.
5. **Given** Interview가 이미 시작된 완독 Reading이고, **When** 사용자가 완독을 취소하려
   하거나 완독일을 수정하려 하면, **Then** 상태와 완독일은 유지되고 변경할 수 없는 이유가
   안내된다.

### 사용자 스토리 3 - Reading 상세에서 현재 상태와 다음 행동 확인 (우선순위: P2)

로그인한 사용자는 Reading 상세 화면에서 선택한 책, 현재 독서 상태와 상태에 맞는 다음
행동을 한눈에 확인할 수 있다.

**우선순위가 높은 이유**: 상태 저장만으로는 사용자가 현재 기록과 다음 단계를 이해하기
어렵다. 최소 상세 화면은 Reading 흐름을 다시 찾고 완독 후 AI Interview로 이어지는 기준
화면이다.

**독립 테스트**: 각 독서 상태의 Reading 상세 화면을 열어 책의 핵심 정보, 현재 상태와
다음 행동이 정확히 구분되고, 완독 상태에서만 AI 독서노트 시작 행동이 표시되는지
확인한다.

**인수 시나리오**:

1. **Given** 사용자가 자신의 Reading 상세 화면을 열고, **When** 화면 표시가 완료되면,
   **Then** 책의 표지(있는 경우), 제목, 저자 등 식별 정보와 현재 독서 상태를 확인할 수
   있다.
2. **Given** Reading이 `읽고 싶음` 또는 `읽는 중`이고, **When** 상세 화면을 보면,
   **Then** 상태를 변경할 수 있는 행동이 보이고 AI 독서노트 시작 행동은 보이지 않는다.
3. **Given** Reading이 `완독`이고, **When** 상세 화면을 보면, **Then** 완독일과
   `AI 독서노트 만들기` 행동을 확인할 수 있다.
4. **Given** 사용자가 Desktop 또는 Mobile Web에서 키보드나 보조 기술을 사용하고,
   **When** Reading 상태를 확인하고 변경하면, **Then** 현재 상태와 변경 결과를 색상에만
   의존하지 않고 구분할 수 있다.

### 예외 상황

- Reading 생성 요청 직전에 같은 사용자의 같은 Book 활성 Reading이 생성된 경우에도 새
  Reading을 추가하지 않고 기존 활성 Reading을 연다.
- 사용자가 Book의 독서 상태를 선택하기 전에는 해당 Book을 조회하거나 선택했다는 이유만으로
  Reading을 자동 생성하지 않는다.
- 사용자가 소유하지 않은 Reading 식별자로 상세 조회나 상태 변경을 요청하면 해당 Reading의
  존재나 내용을 노출하지 않고 접근을 허용하지 않는다.
- 존재하지 않는 Book으로 Reading을 만들거나 존재하지 않는 Reading을 열려고 하면 부분적인
  기록을 남기지 않고 안전한 오류 안내와 돌아갈 행동을 제공한다.
- 현재 상태와 같은 상태로 반복 변경을 요청해도 완독일을 새로 쓰거나 중복 효과를 만들지
  않는다.
- 완독일이 미래이거나 유효한 날짜가 아니면 완독 상태를 저장하지 않고 날짜를 수정할 수
  있도록 안내한다.
- Interview가 시작된 Reading의 완독일 수정 요청은 기존 값을 유지하고, Interview가 기준으로
  삼은 독서 경험을 보존하기 위해 변경할 수 없음을 안내한다.
- 상태 변경 저장에 실패하면 화면이 성공한 것처럼 표시되지 않아야 하며, 이전 상태와
  완독일이 보존되고 다시 시도할 수 있어야 한다.
- 표지, 저자, 출판사 등 선택 서지정보가 누락되어도 제목으로 Reading을 식별할 수 있어야
  하며 누락 정보를 추측해 표시하지 않는다.
- 완독된 과거 Reading만 있는 Book을 다시 선택하면 최근 완독 Reading을 먼저 표시하며,
  사용자가 `다시 읽기`를 선택하기 전에는 새 Reading을 만들지 않는다.
- 인증되지 않은 사용자는 Reading 생성, 상세 조회 또는 상태 변경을 할 수 없다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 Reading을 한 사용자와 한 Book에 연결된 한 번의 독서 경험으로
  관리해야 한다.
- **FR-002**: 시스템은 Reading 상태로 `읽고 싶음`, `읽는 중`, `완독`을 지원해야 한다.
- **FR-003**: 사용자는 이미 읽은 책을 바로 완독으로 등록할 수 있도록 세 상태를 정해진
  순서 없이 선택할 수 있어야 한다.
- **FR-004**: 로그인한 사용자는 자신이 선택한 Book에서 `읽고 싶음`, `읽는 중`, `완독`
  중 하나를 선택해 해당 상태의 Reading을 생성하고 상세 화면에 진입할 수 있어야 한다.
- **FR-005**: 시스템은 사용자가 Book의 독서 상태를 선택하기 전에는 Book 조회 또는 선택만으로
  Reading을 자동 생성해서는 안 된다.
- **FR-006**: 시스템은 같은 사용자와 Book에 `읽고 싶음` 또는 `읽는 중` 상태의 활성
  Reading이 있으면 새 Reading 대신 해당 Reading을 열어야 한다.
- **FR-007**: 시스템은 같은 사용자와 Book에 대한 반복 또는 동시 시작 요청에서도 활성
  Reading을 최대 한 건만 유지해야 한다.
- **FR-008**: 사용자는 자신이 소유한 Reading의 상태를 변경할 수 있어야 하며, 저장된 현재
  상태를 상세 화면에서 확인할 수 있어야 한다.
- **FR-009**: 시스템은 Reading이 완독 상태로 변경될 때 오늘을 기본 완독일로 제시하고,
  사용자가 오늘 또는 과거의 유효한 완독일을 선택해 함께 저장할 수 있게 해야 한다.
- **FR-010**: 시스템은 이미 완독인 Reading에 같은 상태 변경이 반복되어도 기존 완독일을
  변경해서는 안 된다.
- **FR-010A**: 사용자는 Interview가 시작되기 전인 완독 Reading의 완독일을 오늘 또는 과거의
  유효한 날짜로 수정할 수 있어야 하며, 미래 날짜나 유효하지 않은 날짜는 저장할 수 없어야
  한다.
- **FR-011**: 사용자는 Interview가 시작되지 않은 완독 Reading을 `읽고 싶음` 또는
  `읽는 중`으로 되돌릴 수 있어야 하며, 이때 완독일을 제거해야 한다.
- **FR-012**: 시스템은 Interview가 시작된 Reading의 완독 상태 취소와 완독일 수정을
  허용해서는 안 되며, 상태와 완독일을 그대로 보존하고 그 이유를 사용자에게 알려야 한다.
- **FR-013**: 시스템은 같은 Book에 완독된 Reading만 있을 때 최근 완독 Reading을 먼저
  열고, 사용자가 `다시 읽기`를 명시적으로 선택한 뒤 세 독서 상태 중 하나를 고른 경우에만
  기존 기록을 덮어쓰지 않는 별도의 Reading을 선택한 상태로 생성해야 한다.
- **FR-013A**: 사용자가 재독의 초기 상태로 `완독`을 선택하면 오늘을 기본값으로 제시하고,
  사용자가 선택한 오늘 또는 과거의 유효한 완독일을 함께 저장해야 한다.
- **FR-014**: Reading 상세 화면은 Book의 제목과 제공 가능한 핵심 서지정보, 현재 독서 상태,
  완독 상태인 경우 완독일, 상태에 맞는 다음 행동을 표시해야 한다.
- **FR-015**: Reading 상세 화면은 `완독` 상태에서만 `AI 독서노트 만들기` 행동을 표시해야
  한다.
- **FR-016**: 이번 기능의 `AI 독서노트 만들기` 행동은 후속 Interview 시작 흐름의 진입점을
  제공하는 데까지만 책임지며, Interview 생성이나 Book Knowledge 준비를 수행하지 않아야
  한다.
- **FR-017**: Reading 생성과 상태 변경에는 Credit 또는 Coupon이 필요하다는 표현을
  표시하거나 사용량을 변경해서는 안 된다.
- **FR-018**: 시스템은 인증된 사용자에게만 Reading 생성, 상세 조회와 상태 변경을 허용하고,
  사용자가 소유한 Reading에만 접근할 수 있게 해야 한다.
- **FR-019**: Reading 생성 또는 상태 변경이 실패하면 불완전한 Reading, 중복 활성 Reading,
  상태와 완독일이 불일치하는 기록을 남겨서는 안 된다.
- **FR-020**: 상태 변경 결과와 오류 안내는 사용자가 Reading 상태를 변경할 수 있는 모든
  화면 경로에서 일관되어야 한다.
- **FR-021**: Reading 상세와 상태 변경은 Desktop 및 Mobile Web에서 동작하고, 키보드와
  보조 기술 사용자가 현재 상태, 변경 행동과 결과를 색상 외의 정보로 구분할 수 있어야
  한다.
- **FR-022**: 이번 기능은 Reading의 읽기 전 기대와 읽는 중 메모, 개인 Library,
  Book Knowledge 준비, Interview 생성·진행 및 Reflection 생성을 포함하지 않아야 한다.

### 핵심 엔터티 *(기능에 데이터가 포함되는 경우 작성)*

- **Reading**: 한 사용자가 한 Book과 맺는 한 번의 독서 경험이다. 소유 사용자, 대상 Book,
  현재 독서 상태, 생성 시점과 완독일을 가지며 완독된 과거 경험은 재독 Reading과 별도로
  보존된다.
- **Book**: Reading의 대상이 되는 출판 도서이다. 제목과 제공 가능한 서지정보를 통해
  사용자가 Reading 대상을 확인한다.
- **독서 상태**: Reading의 현재 단계를 나타내는 `읽고 싶음`, `읽는 중`, `완독` 중 하나의
  값이다. 완독 상태와 완독일은 서로 일관되어야 한다.
- **활성 Reading**: 같은 사용자와 Book에 대해 아직 완독되지 않은 Reading이다. 중복 생성
  대신 다시 열어야 하며 한 시점에 최대 한 건만 존재한다.
- **Interview 연결 여부**: 완독 취소와 완독일 수정 가능성을 결정하는 Reading의 후속
  상태이다. Interview가 시작되기 전에는 완독 상태와 날짜를 수정할 수 있고, 시작된 뒤에는
  해당 독서 경험의 정체성을 보존한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 신규 Book 선택부터 Reading 생성과 상세 화면 진입까지의 모든 인수 시나리오가
  100% 성공하며, 생성된 Reading은 정확히 한 건이다.
- **SC-002**: 같은 사용자와 Book에 대한 순차 및 동시 시작 인수 테스트에서 중복 활성
  Reading이 0건이고 기존 활성 Reading 재사용률이 100%이다.
- **SC-003**: 세 독서 상태 사이의 허용된 변경 인수 테스트에서 저장 상태와 화면 표시의
  불일치가 0건이다.
- **SC-004**: 완독 진입, 동일 상태 반복, Interview 전 완독 취소 시나리오에서 상태와
  완독일의 일관성이 100% 유지된다.
- **SC-005**: Interview가 시작된 Reading의 완독 취소 시도 인수 테스트에서 허용되지 않은
  상태 변경과 완독일 손실이 각각 0건이다.
- **SC-006**: 완독 Reading 상세 화면의 모든 인수 테스트에서 책 정보, 완독 상태, 완독일과
  AI 독서노트 시작 행동이 누락 없이 표시되고, 미완독 화면에서 해당 시작 행동 노출은
  0건이다.
- **SC-007**: 인증되지 않은 사용자와 다른 사용자의 Reading을 대상으로 한 모든 생성·조회·
  변경 인수 테스트에서 무단 접근 성공과 다른 사용자의 Reading 정보 노출이 각각 0건이다.
- **SC-008**: 상태 저장 실패를 재현한 모든 인수 테스트에서 부분 상태 변경과 잘못된 성공
  표시가 0건이며 사용자는 다시 시도할 수 있다.
- **SC-009**: 1280px Desktop과 375px Mobile에서 키보드만 사용해 Book 선택부터 Reading
  생성, 완독 처리와 다음 행동 확인까지를 각각 2회 연속 2분 이내에 완료한다.

## 가정

- IMP-010의 사용자 인증·소유권 기반과 IMP-020의 Book 기본 도메인, IMP-024의 도서 선택 및
  로컬 Book 등록이 완료되어 있으며 이번 기능은 선택된 Book을 후속 흐름의 입력으로
  사용한다.
- `읽고 싶음`과 `읽는 중`을 활성 Reading으로 보고, 같은 사용자와 Book에는 활성 Reading이
  최대 한 건만 존재한다고 가정한다.
- Reading이 없는 Book에서는 사용자가 `읽고 싶음`, `읽는 중`, `완독` 중 하나를 선택할 때
  해당 상태로 첫 Reading을 생성하며, 상태를 선택하기 전에는 Reading을 만들지 않는다.
- 완독 상태 변경 시 오늘을 완독일 기본값으로 사용하되, 사용자는 실제 완독일에 맞게 오늘
  또는 과거 날짜를 선택하고 이후 수정할 수 있다. 미래 날짜는 허용하지 않는다.
- 같은 Book의 완독 Reading만 존재할 때 Book을 다시 선택하면 최근 완독 Reading을 먼저
  연다. 사용자가 `다시 읽기`를 명시적으로 선택한 뒤 세 독서 상태 중 하나를 고를 때만
  해당 상태의 새 Reading을 생성하며 기존 완독 Reading을 변경하지 않는다.
- Interview 도메인이 아직 구현되지 않은 단계에서도 완독 취소 가능 여부를 후속 기능이
  강제할 수 있는 계약을 유지한다. Bundle 04A에서는 Interview가 없으므로 생성된 Reading의
  완독 상태와 완독일을 수정할 수 있으며, 후속 Interview가 시작되면 둘 다 잠긴다.
- `AI 독서노트 만들기` 행동의 실제 Book Knowledge 준비와 Interview 시작은 Day 05 이후
  범위이다. 이번 기능은 완독 Reading에서 다음 단계가 있음을 보여주는 진입점까지만 다룬다.
- Reading은 무료 기록 공간이며 생성과 상태 변경은 Credit 또는 Coupon 상태에 의존하지
  않는다.
- 읽기 전 기대와 읽는 중 메모는 제품 전체 MVP 범위에는 포함되지만 구현 계획상 Day 12의
  Reading Context 확장으로 분리되어 Bundle 04A에서는 다루지 않는다.
