## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 준비 수준에 맞는 첫 질문 받기 (우선순위: P1)

인터뷰를 시작한 사용자는 선택한 책과 자신의 독서 경험에 맞는 첫 질문을 보고, 부담 없이
자신의 기억과 생각을 답변하기 시작할 수 있다. 책에 대해 확인된 정보가 부족한 경우에도
서비스는 책 내용을 아는 척하지 않고 사용자의 기억에서 출발한다.

**우선순위가 높은 이유**: 첫 질문은 빈 노트의 부담을 대화의 시작으로 바꾸는 핵심 가치이며,
근거가 부족한 책에서도 거짓 전제 없이 작동해야 Core MVP의 제품 가설을 검증할 수 있다.

**독립 테스트**: `READY` 책과 `READY_LIMITED` 책으로 각각 시작된 Interview를 열어 첫 질문을
생성하고, 전자는 확인된 책 맥락을 사용할 수 있으며 후자는 사용자 기억을 먼저 묻고 확인되지
않은 내용을 사실로 단정하지 않는지 확인한다.

**인수 시나리오**:

1. **Given** 준비 수준이 `READY`이고 확인된 Book Knowledge가 있는 진행 중 Interview이며,
   **When** 사용자가 Interview 진행 화면에 처음 진입하면, **Then** 시스템은 Book, Reading과
   확인된 Knowledge를 반영한 첫 질문 하나를 보여준다.
2. **Given** 준비 수준이 `READY_LIMITED`인 진행 중 Interview이며, **When** 사용자가 Interview
   진행 화면에 처음 진입하면, **Then** 시스템은 책의 구체적 내용을 사실로 전제하지 않고 가장
   기억에 남는 주장, 장면, 감정 또는 생각을 묻는 첫 질문 하나를 보여준다.
3. **Given** 동일한 Interview에 답변되지 않은 첫 질문이 이미 존재하고, **When** 사용자가
   화면을 새로 열거나 요청을 반복하면, **Then** 시스템은 새 질문을 중복 생성하지 않고 기존
   질문을 같은 순서로 보여준다.
4. **Given** 첫 질문이 아직 없는 진행 중 Interview이고, **When** 사용자가 Interview 화면에
   진입하면, **Then** 같은 화면에서 질문을 준비 중임을 알 수 있는 Loading 상태를 보여주고
   생성이 완료되면 현재 화면을 첫 질문 상태로 전환한다.

### 사용자 스토리 2 - 한 질문에 집중해 답변하기 (우선순위: P1)

사용자는 일반 채팅 기록에 방해받지 않고 현재 질문 하나에 집중하며, 완성된 문장이 아니어도
기억나는 대로 답변을 작성하고 제출할 수 있다.

**우선순위가 높은 이유**: 사용자가 생각을 꺼내는 부담을 낮추는 집중형 질문 경험은 AfterMuse를
일반 Chat UI나 고정 설문지와 구분하는 핵심 UX다.

**독립 테스트**: 첫 질문이 있는 Interview를 Desktop 및 Mobile Web 크기의 응답으로 열어 책과
현재 질문, 답변 입력, 제출 행동을 식별할 수 있고 키보드만으로 답변을 제출할 수 있는지 확인한다.

**인수 시나리오**:

1. **Given** 첫 질문이 준비된 Interview이고, **When** 사용자가 진행 화면을 열면, **Then** 현재
   책과 질문 하나가 중심에 표시되고 답변 입력 영역과 명확한 제출 행동이 제공된다.
2. **Given** 답변 입력 영역이 표시되었고, **When** 사용자가 입력을 시작하면, **Then** 완성된
   문장을 요구하지 않으며 기억나는 대로 작성해도 된다는 안내를 확인할 수 있다.
3. **Given** 키보드 또는 보조 기술을 사용하는 사용자이고, **When** 질문 화면을 탐색하고
   답변을 제출하면, **Then** 질문, 입력 안내, 오류와 제출 상태를 색상에만 의존하지 않고
   식별하고 조작할 수 있다.

---

### 사용자 스토리 3 - 답변을 먼저 안전하게 보존하기 (우선순위: P1)

사용자는 답변을 제출한 뒤 후속 질문 생성 기능이나 외부 생성 서비스에 문제가 생기더라도
자신이 작성한 답변을 잃지 않고, 저장된 상태를 확인한 후 안전하게 다시 시도할 수 있다.

**우선순위가 높은 이유**: 사용자의 원문 답변은 향후 질문과 Reflection의 근거이므로 외부 실패로
유실되면 제품 신뢰와 사용자 생각의 충실성이 모두 훼손된다.

**독립 테스트**: 유효한 답변을 제출한 뒤 후속 처리가 성공하는 경우와 실패하는 경우를 각각
재현하여, 두 경우 모두 답변 원문이 해당 첫 질문에 한 번만 보존되는지 확인한다.

**인수 시나리오**:

1. **Given** 답변되지 않은 첫 질문이고, **When** 사용자가 유효한 답변을 제출하면, **Then**
   시스템은 답변 원문을 해당 질문에 보존하고 저장 완료 상태를 표시하되 다음 질문을 생성하지
   않는다.
2. **Given** 사용자의 첫 답변이 저장되었고, **When** 저장 완료 응답이 만들어지면, **Then**
   시스템은 후속 분석, Coverage 갱신 또는 질문 생성을 시작하지 않으며 저장된 답변을 그대로
   유지한다.
3. **Given** 동일한 답변 제출이 반복되거나 동시에 처리되고, **When** 처리가 완료되면, **Then**
   해당 질문에는 하나의 답변만 보존되며 원문이 중복되거나 서로 다른 요청으로 덮어써지지 않는다.
4. **Given** 첫 답변 저장이 완료되었고, **When** 사용자가 저장 완료 상태를 확인하면, **Then**
   답변 수정 또는 교체 행동은 제공되지 않으며 확정된 원문이 표시된다.
5. **Given** 사용자가 유효한 답변을 작성했고, **When** 답변 저장 요청 자체가 실패하면,
   **Then** 시스템은 저장 완료로 표시하지 않고 현재 입력 내용을 유지하며 명시적인 재제출
   행동을 제공한다.

### 사용자 스토리 4 - 생성 실패에서 안전하게 회복하기 (우선순위: P2)

사용자는 첫 질문을 만들 수 없는 일시적 오류가 발생해도 Interview와 기존 기록을 잃지 않고,
이해할 수 있는 오류 안내와 재시도 행동을 통해 같은 Interview에서 계속할 수 있다.

**우선순위가 높은 이유**: 질문 생성은 실패 가능한 외부 기능에 의존하므로, 회복 경로가 없으면
사용자는 이미 확정한 독서 경험에서 진행할 수 없게 된다.

**독립 테스트**: 질문 생성의 실패, 시간 초과, 사용할 수 없는 결과를 각각 재현하여 Interview가
유지되고 불완전한 질문이 저장되지 않으며 동일 화면에서 재시도할 수 있는지 확인한다.

**인수 시나리오**:

1. **Given** 답변 Turn이 없는 진행 중 Interview이고, **When** 첫 질문 생성이 실패하거나 30초
   안에 완료되지 않으면, **Then** Interview 상태를 유지하고 재시도 가능한 오류 안내를
   표시하며 불완전한 질문을 남기지 않는다.
2. **Given** 생성 결과가 비어 있거나 질문으로 사용할 수 없는 형식이고, **When** 시스템이 결과를
   검사하면, **Then** 사용자에게 해당 내용을 질문으로 노출하거나 저장하지 않고 재시도를 제공한다.
3. **Given** 첫 질문 생성 실패 후 같은 Interview이며, **When** 사용자가 재시도해 유효한 결과를
   받으면, **Then** 첫 질문 하나가 저장되고 정상 질문 화면으로 이동한다.

### 예외 상황

- 로그인하지 않은 사용자는 Interview 질문이나 답변에 접근할 수 없다.
- 다른 사용자의 Interview에 직접 접근하면 대상의 질문, 답변 또는 존재 여부를 노출하지 않는다.
- 진행 중이 아니거나 대상 Reading·Book 연결이 유효하지 않은 Interview에는 새 질문 또는 답변을
  추가하지 않고 기존 데이터를 보존한다.
- Context에 선택 정보가 없으면 없는 내용을 추측하지 않고 확보된 Book, Reading, Knowledge만
  사용한다.
- `READY_LIMITED` Context에 Book Knowledge가 우연히 존재하더라도 확인된 사실처럼 질문의
  전제로 사용하지 않는다.
- 공백뿐인 답변은 저장하지 않고 사용자가 입력을 보완할 수 있도록 안내한다.
- 2,000자를 넘는 답변은 임의로 잘라 저장하지 않고 최대 길이와 수정 방법을 알린다.
- 답변 저장 요청이 실패하면 작성 중인 입력을 초기화하지 않고, 자동 재시도 없이 사용자가
  다시 제출할 수 있게 한다.
- 질문 또는 답변 제출을 반복해도 Turn 순서가 바뀌거나 중복 Turn이 생기지 않는다.
- 생성된 첫 질문이 여러 문장이거나 300자를 넘으면 사용자에게 노출하거나 저장하지 않고
  사용할 수 없는 결과로 처리한다.
- 생성 결과에 질문 외 지시, 상태 변경 요청 또는 허용되지 않은 참조가 포함되면 이를 실행하거나
  사용자에게 그대로 노출하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 진행 중 Interview의 확정된 Book, Reading 상태, 시작 시점 준비 수준과
  사용 가능한 최소 Book Knowledge를 첫 질문 생성을 위한 Context로 구성해야 한다.
- **FR-002**: Context는 신뢰할 수 있는 시스템 지침과 사용자·외부 출처에서 유래한 내용을
  명확히 구분하고, 사용자 입력이나 외부 내용이 시스템 동작 또는 권한을 변경하는 지시로
  취급되지 않게 해야 한다.
- **FR-003**: 시스템은 다른 사용자의 데이터, 확정되지 않은 Book Knowledge, 관리자 정보,
  Credit 정보 또는 현재 Interview에 속하지 않은 기록을 Context에 포함해서는 안 된다.
- **FR-004**: `READY` Context는 해당 Book에 대해 확보된 최소 Knowledge를 사용할 수 있어야 한다.
- **FR-005**: `READY_LIMITED` Context는 확인되지 않은 책 내용을 배제하고 사용자 기억과 답변을
  우선하도록 명시해야 한다.
- **FR-006**: 시스템은 실제 질문 생성 서비스 없이도 정상, 실패, 시간 초과와 사용할 수 없는
  결과를 재현하여 질문 생성 흐름을 검증할 수 있어야 한다.
- **FR-007**: 질문 생성 기능은 질문 문안을 제안할 수 있지만 Interview 상태, Turn 순서,
  데이터 저장 또는 사용자 권한을 직접 변경할 수 없어야 한다.
- **FR-008**: 시스템은 생성된 첫 질문이 비어 있지 않은 한 문장이고 300자 이하이며 내용
  규칙을 충족하는지 검사한 뒤에만 사용자에게 노출하고 저장해야 한다.
- **FR-009**: `READY`의 첫 질문은 확인된 책 맥락 또는 독서 경험과 관련되어야 하며, Knowledge가
  사용자 자신의 기억이나 해석보다 우위에 있다는 인상을 주어서는 안 된다.
- **FR-010**: `READY_LIMITED`의 첫 질문은 사용자의 기억, 인상, 감정 또는 생각에서 출발해야 하며,
  확인되지 않은 인물, 사건, 주장, 장면이나 결말을 사실로 전제해서는 안 된다.
- **FR-011**: 시스템은 Interview 시작 시 전체 질문 목록을 미리 만들거나 첫 질문을 고정 설문지의
  첫 항목으로 취급해서는 안 된다.
- **FR-012**: 답변되지 않은 첫 질문이 이미 존재하면 반복 접근이나 생성 요청에서도 이를 재사용하고
  새 첫 질문을 중복 생성해서는 안 된다.
- **FR-013**: Interview 화면은 현재 Book 식별 정보와 질문 준비 중인 Loading 상태를 제공하고,
  생성이 완료되면 같은 화면을 현재 질문 하나, 답변 입력 영역, 부담을 낮추는 입력 안내와
  명확한 제출 행동이 있는 질문 상태로 전환해야 한다.
- **FR-014**: 질문 화면은 과거 대화를 메신저 Bubble 목록처럼 중심에 배치하지 않아야 하며,
  사용자가 한 번에 하나의 질문에 집중할 수 있어야 한다.
- **FR-015**: 질문 화면과 답변 제출은 Desktop 및 Mobile Web에서 동작해야 하며, 키보드와
  보조 기술 사용자가 질문, 입력, 제출 상태와 오류를 인식하고 조작할 수 있어야 한다.
- **FR-016**: 시스템은 공백뿐인 답변을 거부하고, 2,000자 이하인 유효한 답변 원문을 해당
  질문 Turn에 보존해야 한다. 2,000자를 넘는 답변은 일부만 저장하지 않고 사용자가 줄일 수
  있도록 최대 길이를 알려야 한다.
- **FR-017**: 시스템은 답변 저장을 후속 분석, Coverage 갱신 또는 다음 질문 생성보다 먼저
  확정해야 한다.
- **FR-017A**: Day 06에서는 답변 저장 성공 직후 저장 완료 상태를 표시하고, 답변 분석,
  Coverage 갱신, 다음 질문 생성 또는 다음 질문 준비 상태를 자동으로 시작하거나 표시해서는
  안 된다.
- **FR-018**: Day 06에서는 답변 저장 이후 분석, Coverage 갱신 또는 질문 생성을 시작하지 않아야
  한다. 향후 후속 처리가 연결되더라도 이미 확정된 답변 원문, Interview와 Turn 순서는 그 처리의
  성공 여부와 무관하게 유지되어야 한다.
- **FR-018A**: 답변 저장 요청 자체가 실패하면 저장 완료 상태를 표시해서는 안 되며, 사용자가
  작성한 현재 입력 내용을 화면에 유지하고 자동 재시도 없이 명시적인 재제출 행동을 제공해야 한다.
- **FR-019**: 답변은 최초 저장 성공 시 확정되어야 하며, 동일한 질문에 대한 반복 또는 동시
  제출은 답변을 중복 생성하거나 이미 확정된 원문을 수정·교체해서는 안 된다.
- **FR-020**: 첫 질문 생성 실패, 30초의 생성 시간 초과 또는 사용할 수 없는 결과가 발생하면 Interview와
  기존 Turn을 보존하고, 불완전한 질문을 저장하지 않으며 같은 Interview 화면에서 재시도 가능한
  Error 상태를 제공해야 한다.
- **FR-021**: 시스템은 사용자가 소유한 진행 중 Interview의 질문과 답변만 조회하거나 변경할 수
  있게 하고, 다른 사용자의 데이터와 존재 여부를 노출해서는 안 된다.
- **FR-022**: 이번 기능은 저장 완료된 답변의 수정·교체, Coverage 생성·갱신, 답변 의미 분석,
  다음 질문 생성, Soft Stop, 이전 답변 보기, Interview Restart 또는 Reflection 생성을
  수행하지 않아야 한다.
- **FR-023**: 이번 기능은 Credit 예약·소비, 자동 Book Knowledge Research, 외부 웹 검색 또는
  질문 생성 기능의 임의 도구 실행을 수행하지 않아야 한다.

### 핵심 엔터티 *(기능에 데이터가 포함되는 경우 작성)*

- **Interview Context**: 특정 Interview의 첫 질문을 만들기 위해 허용된 정보 묶음이다. 확정된
  Book과 Reading, 시작 시점의 `READY` 또는 `READY_LIMITED` 수준, 사용할 수 있는 최소
  Knowledge를 포함하며 출처와 신뢰 경계를 보존한다.
- **Interview Turn**: Interview 안의 순서가 있는 질문·답변 단위다. 이번 기능에서는 첫 질문과
  사용자가 제출한 원문 답변을 나타내며, 같은 Interview 안에서 첫 순서는 하나만 존재한다.
- **Generated Question**: Interview Context를 바탕으로 제안된 첫 질문 후보다. 유효성 검사를
  통과한 단일 질문만 Interview Turn으로 확정되며 자체적으로 상태나 데이터를 변경할 권한은 없다.
- **Answer**: 사용자가 첫 질문에 대해 직접 작성한 원문이다. 해당 Turn과 사용자 소유 관계 안에서
  한 번 보존되며 후속 생성 실패와 무관하게 유지된다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 대표 `READY`와 `READY_LIMITED` 검증 사례의 100%에서 사용자는 Interview 진입 후
  첫 질문 하나를 확인하고 답변 작성을 시작할 수 있다.
- **SC-002**: `READY_LIMITED` 검증 사례의 100%에서 첫 질문은 확인되지 않은 책 내용을 사실로
  전제하지 않고 사용자의 기억, 인상, 감정 또는 생각에서 출발한다.
- **SC-002A**: 사용자에게 노출되고 저장되는 첫 질문은 모두 한 문장이고 300자 이하이며,
  기준을 벗어난 생성 결과는 질문 Turn으로 확정되지 않는다.
- **SC-003**: 답변 저장 성공을 재현한 모든 검증 사례에서 답변 원문이 한 번만 보존되고,
  사용자는 저장 완료 상태를 확인하며 다음 질문이 생성되거나 준비 중인 것으로 안내받지 않는다.
- **SC-003A**: 2,000자 이하의 답변은 원문 전체가 보존되고, 2,000자를 넘는 답변은 일부도
  저장되지 않으며 사용자가 최대 길이를 확인할 수 있다.
- **SC-003B**: 답변 저장 실패를 재현한 모든 검증 사례에서 입력 내용이 현재 화면에 유지되고,
  사용자는 내용을 다시 작성하지 않고 한 번의 명확한 행동으로 재제출할 수 있다.
- **SC-004**: 질문 생성 실패, 30초의 생성 시간 초과와 사용할 수 없는 결과의 모든 검증 사례에서 Interview와
  기존 기록이 유지되고 사용자는 같은 Interview 화면에서 한 번의 명확한 행동으로 재시도할 수 있다.
- **SC-005**: 대표 Desktop 및 Mobile 화면 조건에서 사용자는 현재 질문과 상태를 인식하고,
  키보드만으로 답변 입력·제출 및 오류 복구 행동을 수행할 수 있으며, 질문·입력·오류·제출
  상태를 색상에만 의존하지 않고 구분할 수 있다.
- **SC-006**: 반복 접근과 반복·동시 제출 검증 사례의 100%에서 첫 질문과 답변은 각각 하나만
  유지되며 Turn 순서나 최초 저장된 원문이 바뀌지 않는다.
- **SC-007**: 다른 사용자 또는 로그인하지 않은 사용자의 접근 검증 사례 100%에서 질문과 답변의
  내용 및 대상 존재 여부가 노출되지 않는다.

## 가정

- Bundle 05B에서 한 Reading에 하나의 Interview가 연결되고 Interview 시작 시 Book, Reading과
  Knowledge 준비 수준이 이미 확정되어 있다.
- Core MVP의 Reading Context는 현재 구현된 Reading 상태를 사용하며, 읽기 전 기대와 ReadingEntry는
  후속 Full MVP 범위이므로 존재할 때만 활용하고 이번 기능에서 새 입력 기능을 만들지 않는다.
- 첫 질문의 구체적인 문체는 계획 단계에서 기존 UX 문구를 근거로 정하되, 한 문장·300자 이하의
  열린 질문 하나를 제공한다는 제품 계약은 유지한다.
- 외부 질문 생성 기능의 장애는 일시적일 수 있으며, 자동으로 무한 재시도하지 않고 사용자가
  명시적으로 다시 시도할 수 있게 한다.
- `잘 모르겠어요`와 `건너뛰기`, 답변 분석, Coverage와 다음 질문 연결은 후속 Bundle에서 다룬다.
- 이번 명세의 Desktop/Mobile 지원은 결정적 화면·접근성 계약 검증을 완료 조건으로 하며, 별도
  요청이 없는 실제 브라우저 수동 검증은 선택 사항이다.
