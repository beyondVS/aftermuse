# 기능 사양: Reflection 기본 모델과 생성 Prompt / Adapter

**기능 브랜치**: `feature/day-10-reflection-model-prompt-adapter`

**생성일**: 2026-09-15

**상태**: 초안

**입력**: 사용자 설명: "구현계획 중 10일차 Day 10 — Reflection 기본 모델과 생성 Prompt / Adapter의 명세를 작성한다."

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 초안과 내 수정 내용을 구분해 보존하기 (우선순위: P1)

사용자는 Interview 결과로 만들어진 독서노트 초안을 보존하고, 이후 자신의 수정 내용을 원래 AI 초안과 구분해 남길 수 있다. 이번 작업은 저장·조회 기반을 제공하며 사용자 화면은 후속 작업에서 연결한다.

**우선순위가 높은 이유**: 초안과 사용자 기록을 구분해야 사용자가 자신의 생각을 직접 다듬을 수 있고 원래 초안이 수정으로 유실되지 않는다.

**독립 테스트**: 준비된 초안을 Interview에 연결해 저장·조회하고 별도의 수정본을 저장한 뒤 두 내용을 비교한다. 생성 기능 없이 준비된 내용으로 검증할 수 있다.

**인수 시나리오**:

1. **Given** Reflection 생성 준비가 끝난 소유자의 Interview와 유효한 초안, **When** 초안을 저장하고 다시 조회하면, **Then** 같은 Interview·Reading·책·소유자에 연결된 Markdown 내용과 Draft 상태가 보존된다.
2. **Given** 저장된 AI 초안, **When** 사용자 수정본을 저장하면, **Then** 수정 내용과 원래 AI 초안을 각각 조회할 수 있으며 초안은 바뀌지 않는다.
3. **Given** 수정하지 않은 Draft, **When** 조회하면, **Then** 사용자 수정본이 없음을 구분할 수 있고 초안 생성만으로 완료 상태나 완료 시각이 설정되지 않는다.
4. **Given** 다른 사용자의 Interview 또는 Reflection, **When** 조회나 저장을 요청하면, **Then** 타인의 내용에 접근하거나 그 기록을 변경할 수 없다.

---

### 사용자 스토리 2 - 내가 답한 생각으로 독서노트 초안 만들기 (우선순위: P1)

사용자는 자신이 확정한 Interview 답변을 읽기 쉬운 독서노트로 정리한 초안을 얻는다. 표현과 문단은 다듬되 말하지 않은 의견이나 책의 내용을 덧붙이지 않는다.

**우선순위가 높은 이유**: 사용자의 생각을 대신 만들지 않는 것이 제품의 핵심 신뢰 조건이다.

**독립 테스트**: 도서 맥락이 풍부한 Interview와 제한된 Interview의 답변으로 초안을 생성하고, 각 서술의 근거와 가변 구성을 원문과 대조한다. 저장 없이 생성 결과만 검증할 수 있다.

**인수 시나리오**:

1. **Given** 기억·감정·경험 연결을 표현한 확정 답변들, **When** 초안을 생성하면, **Then** 답변의 의미와 유보 표현을 보존한 비어 있지 않은 Markdown 초안이 반환된다.
2. **Given** 책 정보가 제한된 Interview, **When** 초안을 생성하면, **Then** 책의 줄거리·주장·인물 평가를 새로 보충하지 않고 사용자가 답한 기억과 인상으로 구성한다.
3. **Given** 한 가지 인상만 짧게 표현한 답변, **When** 초안을 생성하면, **Then** 근거가 있는 짧은 기록을 만들고 답하지 않은 주제의 문단이나 필수 분량을 채우지 않는다.
4. **Given** 비문학 주장 중심 답변과 소설 장면 중심 답변, **When** 각각 초안을 생성하면, **Then** 각 답변에 맞는 구성으로 정리하고 동일한 section 종류·개수를 강제하지 않는다.

---

### 사용자 스토리 3 - 생성 방식과 실패에 관계없이 원문 지키기 (우선순위: P2)

사용자는 생성 방식이 바뀌거나 생성에 실패해도 자신의 답변과 기존 독서노트를 잃지 않는다.

**우선순위가 높은 이유**: 생성은 외부 오류 가능성이 있는 작업이므로 기록의 보존과 생성 성공을 분리해야 한다.

**독립 테스트**: 시험용 생성과 현재 지원하는 실제 생성 방식의 동일한 입력·결과 계약을 확인하고, 실패·빈 결과·잘못된 결과에서 원래 기록의 불변을 확인한다.

**인수 시나리오**:

1. **Given** 동일한 유효 입력, **When** 시험용 생성 또는 선택한 실제 생성 방식으로 요청하면, **Then** 모두 같은 검증 조건을 만족하는 Markdown 초안을 제공할 수 있다.
2. **Given** 생성 실패 또는 유효하지 않은 결과, **When** 생성 결과를 처리하면, **Then** 실패로 구분하고 잘못된 초안을 저장하지 않으며 기존 질문·답변·Coverage·독서노트를 보존한다.
3. **Given** 답변 속에 규칙 무시나 다른 사용자 기록 요청이 포함된 Interview, **When** 생성하면, **Then** 해당 문구는 사용자 입력으로 취급되고 생성 규칙이나 접근 범위를 변경하지 않는다.

### 예외 상황

- 확정 답변이 없거나 모두 공백이면 생성 가능한 입력으로 인정하지 않고 초안을 만들지 않는다. 미답변 질문은 생각의 근거로 사용하지 않는다.
- Coverage가 미완료여도 Interview가 생성 준비 상태라면 실제 답변만으로 짧은 초안을 만들 수 있다. 부족한 축을 임의로 채우지 않는다.
- 질문에 포함된 전제, Book Knowledge, 답변 분석 요약은 사용자가 표현하지 않은 생각을 추가하는 근거가 될 수 없다.
- 사용자의 의문·반대·불확실성 또는 서로 다른 감정은 단정적인 동의나 일관된 결론으로 바꾸지 않는다.
- 빈 결과, 잘못된 형식, 허용 범위를 벗어난 내용, timeout 및 설정 오류는 성공한 초안으로 취급하지 않는다.
- 기존 Reflection이 있는 Interview에 새 초안을 저장하려 하면 중복 기록 생성이나 기존 초안·수정본 덮어쓰기를 허용하지 않는다. 생성 전이의 재시도·동시 요청 처리는 Day 11에서 연결한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: Reflection은 Interview와 구분되는 독서노트 결과물이며 하나의 Interview에 최대 하나만 연결되어야 한다. Interview의 Reading·책·소유자와 관계가 일치해야 한다.
- **FR-002**: 유효한 Reflection 초안의 Markdown 본문, 가변 section 구성, Draft 상태 및 생성·갱신 시각을 저장하고 동일한 내용으로 조회할 수 있어야 한다. section은 제목과 내용의 구분 및 순서를 보존해야 한다.
- **FR-003**: AI가 처음 생성한 초안과 선택적인 사용자 수정본을 구분해 보존해야 한다. 수정본 저장이 원래 초안을 변경해서는 안 되며 수정본이 없는 상태를 식별할 수 있어야 한다.
- **FR-004**: 생성·저장·조회·수정본 저장은 소유자의 기록으로 제한해야 한다. Interview 관계가 맞지 않거나 생성 준비가 되지 않은 대상은 초안 저장 및 생성 대상으로 인정하지 않아야 한다.
- **FR-005**: 초안 생성과 수정본 저장만으로 Reflection이나 Interview를 최종 완료 처리해서는 안 된다. 최종 확인·완료는 후속 작업의 명시적 사용자 행동으로 남겨야 한다.
- **FR-006**: 생성 입력은 대상 Interview의 확정 답변 원문과 순서 및 답변 이해에 필요한 질문 문맥을 포함해야 한다. 다른 Interview나 사용자의 기록, 미답변 입력을 포함해서는 안 된다.
- **FR-007**: 생성 규칙은 사용자가 확정 답변에서 표현한 생각만 정리하도록 명시해야 한다. 새로운 신념·해석·평가·경험·책의 사실을 추가하지 않고 질문 전제나 도서 지식을 사용자 의견으로 바꾸지 않아야 한다.
- **FR-008**: 초안은 의미를 유지하는 표현 정리와 문단 재구성을 허용하되 사용자 답변의 불확실성·반대·감정의 강도를 보존해야 한다. section 종류·개수 및 분량은 답변에 따라 달라지며 근거 없는 항목을 채워서는 안 된다.
- **FR-009**: 시험용 생성(fake provider)과 현재 지원하는 실제 생성 방식은 동일한 입력·결과 계약으로 유효한 Markdown 초안을 제공해야 한다. 생성 결과는 저장 여부와 구분해 검증할 수 있어야 한다.
- **FR-010**: 생성 규칙과 사용자 입력의 신뢰 경계를 구분해야 한다. 사용자 입력이나 생성 결과가 다른 기록 접근, 외부 검색, 기록 직접 수정 또는 생성 정책 변경을 지시할 수 없어야 한다.
- **FR-011**: 생성 결과는 정해진 구조, 비어 있지 않은 본문, section과 본문의 일관성, 길이 및 금지 내용 조건을 검증한 뒤에만 초안으로 인정해야 한다. 구체적인 길이 상한과 검증 가능한 근거 표현은 계획 단계에서 확정한다.
- **FR-012**: 생성 작업 자체는 Interview·질문·답변·Coverage·기존 Reflection을 변경하지 않아야 한다. 실패와 출력 거부는 안전한 오류로 구분하고 credential·답변 원문·외부 응답을 오류 출력에 노출하지 않아야 한다.
- **FR-013**: 실제 생성 실패 시 다른 유료 생성 방식으로 자동 전환하거나 자동 재요청해서는 안 된다. 실제 연결 확인은 명시적인 선택으로 분리하며 기본 검증은 실제 credential이나 외부 서비스 없이 실행 가능해야 한다.
- **FR-014**: 이번 범위는 IMP-090의 저장·조회 기반과 IMP-091의 생성 규칙·생성 방식 경계다. 생성 중 화면·실패 화면·Retry·동시 요청 전이(IMP-092), 결과·편집·완료 화면, Home 연계, Credit, 공개·공유 및 Echo는 포함하지 않는다.

### 핵심 엔터티 *(기능에 데이터가 포함되는 경우 작성)*

- **Reflection**: 소유자의 Interview에 연결된 독서노트이며 최초 AI 초안, 선택적인 사용자 수정본, 가변 구성, Draft 상태 및 생성·갱신 시각을 가진다.
- **Reflection section**: 답변에 맞게 선택된 제목과 내용 및 순서를 가진 독서노트 구성 단위다. 고정 Coverage 축 전체를 반드시 포함하지 않는다.
- **Interview 생성 근거**: 생성 준비 상태의 Interview와 순서가 있는 확정 질문·답변이다. 질문은 문맥이며 사용자 답변만 생각의 근거다.
- **초안 생성 결과**: 저장 전 검증 대상인 Markdown 초안과 그 구성이다. 생성 실패 또는 검증 거부와 구분된다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 초안 저장·재조회, 수정본 저장·재조회, 수정본 없음의 세 사례에서 원래 초안과 사용자 수정 내용이 각각 보존되고 초안 유실 및 자동 완료는 0건이다.
- **SC-002**: 풍부한 답변, 제한된 책 정보, 짧은 답변, 의문·반대가 있는 답변의 대표 인수 자료에서 모든 의견·감정·경험·책 관련 서술을 확정 답변과 대조할 수 있고 답변 밖의 생각 추가는 0건이다. 이는 인수 자료의 품질 평가이며 모든 실제 출력의 의미적 정확성을 보장한다는 뜻은 아니다.
- **SC-003**: 비문학과 소설의 대표 인수 자료에서 답변에 맞는 초안 구성을 얻고 근거 없는 필수 section은 0개다.
- **SC-004**: 시험용 생성과 현재 지원하는 실제 생성 방식 각각에서 동일한 인수 조건을 만족하는 초안을 얻을 수 있다. 실제 연결 결과는 선택한 환경에서 별도 기록한다.
- **SC-005**: 생성 실패, 빈 결과, 잘못된 결과, 생성 대상 부적합 및 타인 접근 사례에서 잘못된 초안 저장과 기존 질문·답변·Coverage·초안·수정본 변경은 0건이다.
- **SC-006**: 같은 Interview에 초안을 다시 저장하려는 사례에서 Reflection 수는 최대 1개이고 최초 초안과 기존 수정본은 유지된다.

## 가정

- 기준 문서는 [PRD §9](../../docs/AfterMuse_MVP_PRD_v4.md), [Architecture Decisions §10.3–10.4 및 상태 모델](../../docs/AfterMuse_Architecture_Decisions_v4.md), [구현 계획 Day 10](../../docs/AfterMuse_MVP_Implementation_Plan_v5.md)이다. 이번 명세는 기존 제품 정책을 변경하지 않는다.
- 선행 작업은 IMP-050(Interview), IMP-060 및 IMP-073(생성 경계와 Interview 근거)이며 IMP-091은 IMP-090을 선행한다. 기존 `REFLECTION_READY`는 Coverage 전체 완료와 별개인 생성 준비 상태로 사용한다.
- 이번 생성 근거는 구현 계획의 제한에 따라 Interview 확정 답변으로 한정한다. 별도의 Reading 메모를 추가 근거로 사용하는 기능은 포함하지 않는다. 도서 식별 정보는 기록 연결용이며 새 내용 생성의 근거가 아니다.
- 기존 지원 생성 방식은 fake, OpenAI, Gemini, Ollama다. 새로운 provider 도입이나 모델 다운로드는 포함하지 않는다.
- 저장·조회 및 수정본 보존은 화면 없이 독립 검증 가능해야 한다. 사용자에게 편집·완료 행동을 제공하는 UI와 최종 상태 전이는 후속 명세에서 다룬다.
- 의미적 충실성은 형식 검사만으로 완전히 증명할 수 없으므로 대표 답변과 초안의 대조 평가를 계획에 포함한다. 실제 브라우저 조작은 이번 작업의 필수 완료 조건이 아니다.
