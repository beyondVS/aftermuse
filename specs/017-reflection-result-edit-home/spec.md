## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 생성된 독서노트를 내 기록으로 읽기 (우선순위: P1)

사용자는 Interview 뒤 생성된 Reflection을 AI 작업 결과가 아니라 자신이 남긴 독서 에세이 형태로 읽는다. 책 제목, 저자, 작성일과 본문이 명확히 구분되고, 긴 글도 흐름을 잃지 않고 읽을 수 있으며 수정 또는 Home 이동을 바로 선택할 수 있다.

**우선순위가 높은 이유**: Interview 결과를 사용자의 기록으로 돌려주는 핵심 산출물이며, 읽기 경험이 성립해야 수정·완료·재진입의 가치도 생긴다.

**독립 테스트**: 소유자에게 생성된 짧은 Reflection과 긴 Reflection을 각각 열어 책 정보, 날짜, 전체 본문, 수정 및 Home 이동 진입점을 확인한다. 수정 저장이나 Home 최근 기록이 없어도 결과 화면의 가치를 독립적으로 검증할 수 있다.

**인수 시나리오**:

1. **Given** 사용자 소유의 Reflection 초안이 생성된 상태, **When** 결과 화면을 열면, **Then** 책 제목·저자·작성일·Reflection 본문이 서로 구분되어 표시되고 전체 본문을 읽을 수 있다.
2. **Given** 여러 문단과 가변적인 소제목을 가진 긴 Reflection, **When** 대표 Desktop 또는 Mobile 폭에서 읽으면, **Then** 글의 순서와 구획이 유지되고 가로 스크롤 없이 읽을 수 있다.
3. **Given** Reflection 결과 화면, **When** 사용자가 다음 행동을 찾으면, **Then** 수정과 Home 이동 진입점을 명확히 구분해 사용할 수 있다.
4. **Given** 사용자 입력에서 유래한 서식 또는 특수 문자열을 포함한 Reflection, **When** 결과 화면을 열면, **Then** 기록의 허용된 문서 구조는 보존되지만 실행 가능한 콘텐츠나 페이지 구조를 훼손하는 내용은 동작하지 않는다.
5. **Given** 다른 사용자의 Reflection 또는 존재하지 않는 Reflection 식별자, **When** 결과 화면에 접근하면, **Then** 해당 기록의 존재나 내용을 확인할 수 없다.

### 사용자 스토리 2 - 초안을 수정하고 최종 기록으로 확인하기 (우선순위: P1)

사용자는 AI가 만든 초안을 직접 고쳐 자신의 표현을 보완하고 저장할 수 있다. 저장 결과를 즉시 확인하며, 내용 검토를 마쳤을 때 별도의 완료 확인을 거쳐 최종 독서노트로 확정한다.

**우선순위가 높은 이유**: AI 초안과 사용자 기록을 구분하고 사용자가 최종 내용에 대한 통제권을 갖게 하는 핵심 신뢰 계약이다.

**독립 테스트**: Reflection 초안의 본문을 수정·저장하고 결과 화면에서 수정본이 표시되는지 확인한 뒤, 완료 확인을 거쳐 최종 상태와 내용이 유지되는지 검증한다. Home 연계나 검증용 책 세트 없이도 독립적으로 검증할 수 있다.

**인수 시나리오**:

1. **Given** 사용자 소유의 완료 전 Reflection, **When** 수정 화면을 열면, **Then** 현재 사용자에게 표시되는 최신 본문이 편집 가능한 상태로 제공된다.
2. **Given** 사용자가 유효한 수정 내용을 입력한 상태, **When** 저장하면, **Then** 저장 완료 피드백이 즉시 제공되고 결과 화면으로 돌아가 수정된 내용이 표시된다.
3. **Given** 사용자가 수정 내용을 저장한 Reflection, **When** 결과 화면을 다시 열면, **Then** AI 초안 대신 가장 최근에 저장한 사용자 수정본이 유지된다.
4. **Given** 비어 있거나 허용 길이를 벗어난 수정 내용, **When** 저장을 시도하면, **Then** 이해 가능한 오류를 받고 기존 저장 내용은 바뀌지 않으며 입력을 고쳐 다시 시도할 수 있다.
5. **Given** 저장 중 충돌 또는 일시적인 오류, **When** 저장이 완료되지 않으면, **Then** 성공으로 표시되지 않고 이미 보존된 Reflection과 AI 초안은 변경되지 않는다.
6. **Given** 완료 전 Reflection의 내용을 확인한 사용자, **When** 최종 완료를 선택하고 확인하면, **Then** 현재 표시된 본문이 최종 기록으로 확정되고 해당 Reflection과 Interview가 완료 상태로 일관되게 전환된다.
7. **Given** 완료 확인 단계, **When** 사용자가 취소하면, **Then** Reflection은 완료 전 상태로 유지되고 수정 또는 검토를 계속할 수 있다.
8. **Given** 이미 완료된 Reflection, **When** 결과 화면을 다시 열면, **Then** 최종 내용과 완료 상태가 유지되며 이번 기능 범위에서 다시 초안 상태로 되돌리거나 내용을 덮어쓸 수 없다.
9. **Given** 다른 사용자의 Reflection 또는 완료된 Reflection, **When** 수정·저장·완료 행동을 직접 요청하면, **Then** 기록의 내용과 상태가 변경되지 않는다.

### 사용자 스토리 3 - Home에서 최근 독서노트로 돌아가기 (우선순위: P1)

사용자는 Reflection을 생성하거나 수정·완료한 뒤 Home으로 이동하고, 최근 독서노트 영역에서 자신의 가장 최근 기록을 확인해 결과 화면으로 다시 들어간다.

**우선순위가 높은 이유**: 생성 직후 URL을 잃어도 기록을 다시 찾게 해 Core Loop를 닫으며, 전체 서재 기능 없이도 최소한의 재진입을 보장한다.

**독립 테스트**: 한 사용자에게 생성 시점 또는 최근 활동 시점이 다른 Reflection을 준비하고 Home에서 가장 최근 항목과 독서노트 보기 행동을 확인한다. 전체 Library나 필터 없이 재진입 경로만 독립적으로 검증할 수 있다.

**인수 시나리오**:

1. **Given** 사용자에게 Reflection이 하나 이상 있는 상태, **When** Home을 열면, **Then** 최근 독서노트 영역에 가장 최근에 생성하거나 수정·완료한 자신의 Reflection 하나가 표시된다.
2. **Given** Home의 최근 독서노트, **When** 독서노트 보기를 선택하면, **Then** 같은 Reflection의 결과 화면으로 이동하고 최신 저장 내용이 표시된다.
3. **Given** 완료 전 초안을 생성하거나 수정한 상태, **When** Home으로 이동하면, **Then** 해당 초안도 최근 독서노트로 다시 찾을 수 있고 ‘작성 중’으로 표시되어 완료된 기록과 구분된다.
4. **Given** 완료된 Reflection, **When** Home에서 확인하면, **Then** 완료된 독서노트임을 이해할 수 있고 결과 화면으로 다시 들어갈 수 있다.
5. **Given** 사용자에게 Reflection이 없는 상태, **When** Home을 열면, **Then** 최근 독서노트 항목을 꾸며내지 않으며 기존 Reading 및 진행 중 Interview 행동은 그대로 사용할 수 있다.
6. **Given** 여러 사용자의 Reflection이 존재하는 상태, **When** 한 사용자가 Home을 열면, **Then** 다른 사용자의 기록이나 메타데이터는 최근 독서노트 선정과 표시에 포함되지 않는다.

### 사용자 스토리 4 - 대표 책 세트로 다음 검증 준비하기 (우선순위: P2)

제품 검증 담당자는 정보가 충분한 책과 제한적인 책을 포함한 최소 대표 세트를 반복해서 준비하여, 다음 단계의 전체 Core Loop 검증에서 서로 다른 지식 조건을 비교할 수 있다.

**우선순위가 높은 이유**: Day 13 검증을 개인별 임의 데이터에 의존하지 않게 하고, 정보가 부족한 책에서도 거짓 전제 없이 유용하게 동작한다는 핵심 가설을 확인할 기반을 제공한다.

**독립 테스트**: 비운영 검증 환경에서 대표 세트를 준비한 뒤 최소 3권의 서로 구분되는 책, 정보가 준비된 책과 제한적인 책의 포함 여부, 반복 준비 결과의 중복 여부를 확인한다. 실제 전체 E2E 수행 없이 데이터 준비 계약만 검증할 수 있다.

**인수 시나리오**:

1. **Given** 비운영 검증 환경, **When** 대표 책 세트를 준비하면, **Then** 서로 구분되는 책이 최소 3권 제공된다.
2. **Given** 준비된 대표 세트, **When** 장르와 도서 정보 조건을 확인하면, **Then** 검증된 Seed Knowledge를 가진 비문학과 문학이 각각 1권이고 제한된 정보로 Interview를 진행하는 책이 1권이다.
3. **Given** 대표 세트가 이미 준비된 환경, **When** 같은 준비 작업을 다시 수행하면, **Then** 동일 책이나 관련 준비 데이터가 중복 생성되지 않고 같은 검증 조건으로 수렴한다.
4. **Given** 운영 또는 공유 데이터 환경, **When** 일반 애플리케이션 동작이 수행되면, **Then** 검증용 데이터가 자동으로 추가되거나 실제 사용자 기록을 변경하지 않는다.

### 예외 상황

- 책 저자 정보가 없으면 결과 화면은 임의의 저자를 만들지 않고, 사용 가능한 책 정보만 자연스럽게 표시한다.
- Reflection의 최초 생성일과 최근 수정일이 다르면 작성일의 의미를 일관되게 유지하고, 최근 항목 선정은 사용자의 마지막 Reflection 활동을 반영한다.
- 수정 없이 저장하거나 동일 요청이 반복되어도 사용자 수정본의 의미 없는 중복 버전이나 중복 완료 처리가 생기지 않는다.
- 사용자가 여러 창에서 같은 Reflection을 수정해 오래된 내용으로 저장하려는 경우, 더 최신의 저장 내용을 조용히 덮어쓰지 않고 충돌을 알린다.
- 완료 요청과 수정 저장 요청이 경합하면 최종 내용과 완료 상태가 서로 다른 시점의 값으로 분리되지 않고 하나의 일관된 결과로 수렴한다.
- 저장 또는 완료 응답을 받지 못해 사용자가 다시 요청해도 이미 적용된 결과를 중복 적용하지 않는다.
- Home의 최근 대상이 삭제되었거나 접근 불가능해진 경우 다른 사용자의 항목으로 대체하지 않고 안전한 빈 상태로 수렴한다.
- 매우 긴 단어, 링크 형태 문자열, 인용문, 목록 및 여러 소제목이 있어도 본문을 잃거나 주요 이동 행동을 가리지 않는다.
- 검증용 책 준비 중 일부 단계가 실패하면 성공한 것처럼 표시하지 않으며, 재실행 시 안전하게 완전한 대표 세트로 수렴한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 생성된 Reflection의 정식 결과 화면에 책 제목, 사용 가능한 저자 정보, 작성일 및 현재 유효한 전체 본문을 명확히 구분해 표시해야 한다.
- **FR-002**: 결과 화면은 고정된 소제목 구성을 강제하지 않고 Reflection이 가진 문단·소제목·목록·인용 등 가변적인 문서 구조와 순서를 읽을 수 있게 보존해야 한다.
- **FR-003**: 결과 화면은 Chat transcript나 AI 생성 도구의 상태보다 독서노트 본문을 주된 콘텐츠로 표현하고, AI가 사용자의 최종 저자처럼 보이게 하는 표현을 사용하지 않아야 한다.
- **FR-004**: 긴 Reflection은 대표 Desktop과 Mobile 폭에서 가로 스크롤 없이 읽을 수 있어야 하며, 제목·메타데이터·본문의 시각적 계층과 키보드로 접근 가능한 수정 및 Home 이동 행동을 제공해야 한다.
- **FR-005**: Reflection에서 유래한 콘텐츠는 허용된 문서 표현만 표시하고 실행 가능한 콘텐츠, 위험한 외부 동작 또는 페이지 구조 변경으로 해석되지 않아야 한다.
- **FR-006**: 결과 조회, 수정, 저장 및 완료 행동은 인증된 Reflection 소유자에게만 허용해야 하며, 권한이 없는 요청에 기록의 존재·내용·상태를 노출하거나 변경해서는 안 된다.
- **FR-007**: 완료 전 Reflection의 수정 화면은 AI 초안 또는 가장 최근 사용자 수정본 중 현재 결과 화면에 표시되는 본문을 편집 시작값으로 제공해야 한다.
- **FR-008**: 사용자는 완료 전 Reflection의 본문을 직접 수정하고 저장할 수 있어야 하며, 저장 성공 시 즉시 이해 가능한 피드백을 받은 뒤 수정된 결과 화면으로 돌아가야 한다.
- **FR-009**: 사용자 수정본은 공백만으로 구성될 수 없고 기존 Reflection의 허용 범위를 넘을 수 없으며, 유효하지 않은 입력은 이유와 수정 방법을 알 수 있게 안내해야 한다.
- **FR-010**: 저장 실패나 충돌은 성공으로 표시하지 않아야 하며, 이미 보존된 AI 초안과 최신 사용자 수정본을 삭제하거나 조용히 덮어써서는 안 된다.
- **FR-011**: 사용자가 수정본을 저장하더라도 최초 AI 초안은 생성 근거와 원본으로 보존되어야 하며, 결과 화면에는 가장 최근에 저장된 사용자 수정본을 우선 표시해야 한다.
- **FR-012**: 시스템은 AI 초안 생성과 사용자 최종 완료를 서로 다른 상태로 구분하고, 사용자가 현재 내용을 확인한 뒤 명시적으로 완료를 확정할 수 있어야 한다.
- **FR-013**: 완료 확인은 취소 가능한 확인 단계를 제공해야 하며, 확정 시 현재 유효 본문, Reflection 완료 상태, 완료 시각 및 연결된 Interview 완료 상태를 하나의 일관된 결과로 보존해야 한다.
- **FR-014**: 완료된 Reflection은 결과 화면에서 다시 읽고 Home에서 다시 열 수 있어야 하며, 이번 기능 범위에서는 수정, 초안 복귀 또는 재완료 행동을 허용하지 않아야 한다. 단, 응답 유실로 동일 완료 POST가 재전송되면 추가 쓰기 없이 기존 완료 결과로 수렴해야 한다.
- **FR-015**: 반복·동시 저장 및 완료 요청은 사용자 수정본과 완료 전이를 중복 적용하지 않고 같은 최종 결과로 안전하게 수렴해야 한다.
- **FR-016**: Home은 현재 사용자의 Reflection 중 마지막 생성·수정·완료 활동이 가장 최근인 항목 하나를 최근 독서노트로 선정하고, 책 식별 정보, 기록 상태 및 결과 화면 진입 행동을 제공해야 한다.
- **FR-017**: 완료 전 Reflection도 Home의 최근 독서노트에서 재진입할 수 있어야 하며, ‘작성 중’ 상태로 표시해 완료된 기록과 명확히 구분해야 한다.
- **FR-018**: Reflection이 없는 사용자의 Home은 허위 최근 항목을 표시하지 않고, 기존의 읽는 중인 책·독서노트를 기다리는 책·진행 중 Interview 상태와 행동을 변경 없이 유지해야 한다.
- **FR-019**: 최근 독서노트 선정과 표시는 현재 사용자의 기록으로 제한하고, 접근 불가능한 기록을 다른 사용자의 데이터나 오래된 캐시로 대체해서는 안 된다.
- **FR-020**: 시스템은 비운영 검증 환경에서 반복 준비 가능한 서로 다른 책 최소 3권의 대표 세트를 제공해야 한다.
- **FR-021**: 대표 책 세트는 검증된 Seed Knowledge가 있는 비문학 1권과 문학 1권, 제한된 정보 조건으로 Interview를 진행할 책 1권으로 구성하고, 각 장르와 지식 조건을 검증 담당자가 구분할 수 있어야 한다.
- **FR-022**: 대표 세트의 반복 준비는 같은 책과 관련 준비 데이터를 중복 생성하지 않아야 하며, 일반 사용자 흐름이나 운영·공유 데이터에 자동으로 적용되어서는 안 된다.
- **FR-023**: 결과·수정·완료·Home 재진입의 정상, 빈 상태, 유효성 오류, 충돌 및 권한 거부는 색상만이 아닌 텍스트로 구분되어야 한다. 본문, 메타데이터, 상태, 오류 및 핵심 행동은 프로젝트의 접근성 대비 기준을 충족하는 기존 디자인 토큰을 사용하고 키보드로 사용할 수 있어야 한다.
- **FR-024**: 이번 범위는 IMP-093의 정식 결과 화면, IMP-094의 수정·최종 확인·Home 최소 재진입 및 IMP-100의 대표 검증용 책 세트다. 전체 Library와 다중 Reflection 탐색·필터·정렬, 공유·공개, Reader Insight 및 공용 파생 데이터 생성, Credit 소비, Reflection 재생성, 완료 후 재편집·버전 이력 UI, 실제 Provider 품질 조정과 Day 13 전체 E2E 수행은 포함하지 않는다.

### 핵심 엔터티 *(기능에 데이터가 포함되는 경우 작성)*

- **Reflection 초안**: 한 Interview에서 생성된 사용자의 독서노트 후보 원문이다. 사용자 수정 여부와 관계없이 최초 생성 결과로 보존되며 최종 완료와 구분된다.
- **사용자 수정본**: 사용자가 초안을 직접 보완해 저장한 최신 본문이다. 존재하면 결과 화면과 후속 편집의 기준이 되지만, 저장만으로 최종 완료를 의미하지 않는다.
- **완료된 Reflection**: 사용자가 현재 본문을 확인하고 명시적으로 완료한 최종 독서 기록이다. 완료 시각을 가지며 연결된 Interview의 완료 상태와 일치한다.
- **최근 독서노트 항목**: 현재 사용자의 Reflection 중 마지막 생성·수정·완료 활동이 가장 최근인 하나를 Home에서 요약하고 결과 화면으로 연결하는 재진입 표현이다.
- **검증용 책 항목**: 다음 단계 Core Loop 검증에 사용할 책과 도서 정보 조건을 나타낸다. 최소한 책 식별 정보와 Seed Knowledge 보유 또는 제한된 정보 조건을 구분한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 짧은 본문, 20개 이상 문단을 가진 긴 본문, 가변 소제목·목록·인용을 포함한 대표 결과 화면 사례 100%에서 책 정보·작성일·전체 본문이 구분되어 순서 손실 없이 표시된다.
- **SC-002**: 결과·수정 화면의 대표 장문 사례 100%에서 본문 container와 form control은 사용 가능한 폭을 넘지 않고, 매우 긴 token은 줄바꿈되며, 행동 영역은 좁은 폭에서 여러 줄로 배치될 수 있다. 수정·저장·완료·Home 이동은 native link·button·label을 통해 키보드로 실행할 수 있다.
- **SC-003**: 유효한 수정의 대표 시나리오 100%에서 사용자는 한 번의 저장 행동 후 성공 피드백과 수정된 결과 화면을 확인하며, 다시 열었을 때 같은 수정본이 유지된다.
- **SC-004**: 공백, 허용 길이 초과, 저장 오류 및 오래된 수정 충돌의 대표 시나리오에서 기존 AI 초안 또는 최신 사용자 수정본의 유실과 조용한 덮어쓰기는 0건이다.
- **SC-005**: 완료, 완료 취소, 반복 완료 및 수정·완료 경합의 대표 시나리오 100%에서 Reflection과 Interview 상태가 일치하고 최종 본문은 정확히 하나이며, 중복 완료 적용은 0건이다.
- **SC-006**: Reflection 생성·수정·완료 후 Home 재진입의 대표 시나리오 100%에서 최근 독서노트 보기를 한 번 선택해 동일 기록의 최신 본문에 도달한다.
- **SC-007**: Reflection 없음, 완료 전 초안, 완료 기록 및 여러 기록이 있는 Home 사례 100%에서 최근 항목과 상태가 정의된 선정 규칙대로 표시되고 기존 Reading 및 Interview 핵심 행동의 손실은 0건이다.
- **SC-008**: 타인 Reflection의 조회·수정·저장·완료와 Home 혼입을 시도하는 대표 권한 시나리오에서 노출되거나 변경된 타인 데이터는 0건이다.
- **SC-009**: 검증용 세트 준비 후 Seed Knowledge가 있는 비문학 1권과 문학 1권, 제한된 정보 조건의 책 1권이 존재하며, 연속 두 번 준비해도 중복 책 또는 중복 준비 데이터는 0건이다.
- **SC-010**: 결과 화면의 대표 콘텐츠 안전성 사례에서 실행된 사용자 유래 스크립트·위험한 외부 동작·페이지 구조 훼손은 0건이다.

## 가정

- 기준 문서는 [PRD의 Reflection 요구사항](../../docs/AfterMuse_MVP_PRD_v4.md), [Architecture Decisions의 Reflection Content와 상태 모델](../../docs/AfterMuse_Architecture_Decisions_v4.md), [UI/UX Guide의 Home 및 Reading Note 결과 화면](../../docs/AfterMuse_UI_UX_and_Design_Implementation_Guide_v8.md), [구현 계획 Day 12](../../docs/AfterMuse_MVP_Implementation_Plan_v5.md)다. 이번 명세는 기존 제품 정책을 변경하지 않는다.
- Day 10과 Day 11에서 Interview당 단일 Reflection 초안, 최초 AI 초안과 선택적 사용자 수정본을 구분할 기반, 생성 성공 후 소유자만 접근 가능한 임시 결과 화면이 제공되었다고 가정한다.
- 사용자 수정 저장과 최종 완료는 다른 행동이다. 수정본을 저장한 초안은 계속 수정·검토할 수 있으며 명시적인 완료 확인 전에는 최종 기록으로 취급하지 않는다.
- 완료된 Reflection은 Day 12에서 읽기 전용 최종 기록이다. 재편집이나 초안 복귀는 허용하지 않으며, 별도의 후속 정책이 승인되기 전에는 완료 기록을 덮어쓰지 않는다.
- 작성일은 Reflection이 처음 생성된 날짜를 의미한다. Home의 최근 항목 선정에는 생성·수정·완료 중 마지막 Reflection 활동 시점을 사용하되, 화면에서 작성일과 최근 활동일을 혼동시키지 않는다.
- 저자 정보가 없는 책은 임의의 대체값을 만들지 않는다. 결과 화면은 사용 가능한 책 메타데이터만 표시한다.
- Home은 전체 독서노트 목록이 아니라 가장 최근 Reflection 하나의 최소 재진입만 제공한다. 전체 Library와 여러 Reflection 탐색은 후속 IMP-122 범위다.
- 대표 책 세트는 개발·테스트·검증처럼 명시적으로 선택한 비운영 환경에서만 준비하며, 실제 사용자 데이터나 운영 데이터를 생성·변경하지 않는다.
- Day 12는 Day 13의 E2E 검증을 위한 데이터와 경로를 준비하지만 실제 브라우저 E2E 수행이나 반복 성공률을 완료 조건으로 삼지 않는다. 반응형·접근성·상태 전이는 결정적인 화면 응답과 상태 계약으로 우선 검증한다.
- Reflection 완료에 따른 Credit 소비, Reader Insight, Evaluation 또는 Knowledge Candidate 생성은 후속 구현 범위이며, Day 12 완료 처리만으로 해당 파생 동작을 선행하지 않는다.
