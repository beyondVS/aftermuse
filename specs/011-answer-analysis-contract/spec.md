## Clarifications

### Session 2026-09-10

- Q: 각 Coverage 변경 후보가 사용자 답변의 어느 부분에 근거하는지 분석 결과에 함께 포함해야 하나요? → A: 각 후보에 답변 원문의 짧은 근거 인용을 필수로 연결한다.
- Q: 유효한 답변 분석 결과를 Bundle 07B에서 영속 기록으로 저장해야 하나요? → A: Bundle 07B에서는 분석 결과를 반환만 하고 저장하지 않는다.
- Q: low-information 답변의 `답변 의미` 값은 어떤 형태로 반환해야 하나요? → A: `답변 의미` 필드는 존재하되 값은 `null`로 반환한다.
- Q: 답변이 현재 Coverage와 같은 수준의 내용만 반복하면 해당 축의 변경 후보를 다시 반환해야 하나요? → A: 현재 Coverage보다 높은 상태로 올리는 후보만 반환한다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 답변에서 드러난 생각을 일관되게 분석하기 (우선순위: P1)

인터뷰에서 답변을 확정한 사용자는 그 답변에 실제로 담긴 핵심 의미와 어떤 Core Coverage가
얼마나 드러났는지를 일관된 분석 결과로 얻는다. 이 결과는 이후 질문이 사용자의 말을 반복하거나
사용자가 말하지 않은 생각을 전제하지 않도록 하는 근거가 된다.

**우선순위가 높은 이유**: 답변에 근거한 구조화된 분석이 없으면 Coverage 갱신과 적응형 질문이
자유 형식 답변을 신뢰성 있게 사용할 수 없고, AfterMuse가 사용자의 생각을 대신 만들어낼 위험이
커진다.

**독립 테스트**: 질문과 그에 대한 확정 답변, 현재 Core Coverage를 입력해 분석을 수행하고,
반환된 의미 요약과 Coverage 변경 후보가 답변 원문의 후보별 근거 인용으로 뒷받침되며 허용된
구조만 포함하는지 확인한다.

**인수 시나리오**:

1. **Given** 사용자가 기억에 남은 장면과 그 이유를 구체적으로 답한 Turn이고, **When** 답변을
   분석하면, **Then** 결과는 답변에 담긴 의미를 간결하게 나타내고 `MEMORY`에 대한 유효한
   Coverage 변경 후보를 포함하며 low-information이 아닌 것으로 판정한다.
2. **Given** 하나의 답변에 평가와 개인 경험의 연결이 함께 드러나고 현재 두 축이 아직 충분히
   다뤄지지 않은 Interview이고, **When** 답변을 분석하면, **Then** 결과는 `REACTION`과
   `CONNECTION` 각각에 대해 답변이 뒷받침하는 변경 후보를 함께 반환할 수 있다.
3. **Given** 답변에 특정 Core Coverage를 뒷받침하는 내용이 없고, **When** 답변을 분석하면,
   **Then** 결과는 해당 축을 추측해 채우거나 현재 Coverage를 낮추는 후보를 반환하지 않는다.
4. **Given** 답변 하나가 여러 Core Coverage 축을 뒷받침하고, **When** 답변을 분석하면,
   **Then** 각 변경 후보는 해당 축의 판정을 뒷받침하는 답변 원문의 짧은 근거 인용을 별도로
   포함한다.
5. **Given** 답변이 특정 축의 현재 Coverage와 같은 수준의 의미만 반복하고, **When** 답변을
   분석하면, **Then** 의미와 low-information 판정은 정상적으로 반환하되 해당 축의 변경 후보는
   반환하지 않는다.

---

### 사용자 스토리 2 - 정보가 부족한 답변을 구분하기 (우선순위: P1)

사용자가 질문에 답할 내용이 없거나 의미를 구체화하기 어려운 짧고 모호한 답변을 남겨도,
시스템은 이를 일반 답변과 구분한다. 이후 흐름은 이 판정을 이용해 같은 주제를 무리하게
파고드는 일을 줄일 수 있다.

**우선순위가 높은 이유**: 정상 답변과 low-information 답변의 구분은 Bundle 07B의 명시적 완료
조건이며, 사용자 피로를 줄이는 후속 종료 정책의 필수 입력이다.

**독립 테스트**: `잘 모르겠어요`, `딱히 없어요`, `그냥 괜찮았어요`처럼 질문에 대한 구체적
정보가 없는 답변과 짧지만 명확한 사실·감정·평가가 있는 답변을 각각 분석해 판정과 Coverage
후보를 비교한다.

**인수 시나리오**:

1. **Given** 질문에 대한 기억·평가·연결·여운을 드러내지 않는 회피성 또는 무내용 답변이고,
   **When** 답변을 분석하면, **Then** 결과는 low-information으로 판정하고 `답변 의미`를
   `null`, Coverage 변경 후보를 빈 집합으로 반환한다.
2. **Given** 문장은 짧지만 `결말이 허무했어요`처럼 질문과 관련된 구체적인 감정이나 판단이
   드러난 답변이고, **When** 답변을 분석하면, **Then** 길이만을 이유로 low-information으로
   판정하지 않고 답변이 뒷받침하는 의미와 Coverage 후보를 반환한다.
3. **Given** 답변 일부에 `잘 모르겠지만` 같은 표현이 있어도 이어지는 내용에 구체적인 생각이
   담겨 있고, **When** 답변을 분석하면, **Then** 특정 문구의 존재만으로 전체 답변을
   low-information으로 판정하지 않는다.

---

### 사용자 스토리 3 - 분석 실패와 부정확한 결과로부터 기록 보호하기 (우선순위: P2)

사용자는 답변 분석 기능이 지연되거나 잘못된 결과를 내더라도 이미 저장한 답변과 Interview
상태가 손상되지 않는 경험을 한다. 분석 결과는 허용된 계약을 통과한 경우에만 후속 흐름의
입력으로 사용할 수 있다.

**우선순위가 높은 이유**: 답변은 사용자의 원본 기록이고 외부 분석은 실패 가능하며 신뢰할 수
없는 경계다. 검증되지 않은 결과가 상태 변경으로 이어지면 질문 품질뿐 아니라 사용자 생각의
충실성까지 훼손한다.

**독립 테스트**: 분석 시간 초과·일시 장애·해석 불가능한 결과와 답변에 없는 의미, 알 수 없는
Coverage 축·상태 또는 과도한 길이를 포함한 결과를 각각 제공하고, 모두 안전한 실패로 처리되어
답변과 Interview 상태가 그대로 유지되는지 확인한다.

**인수 시나리오**:

1. **Given** 답변이 이미 확정된 Turn이고, **When** 분석이 시간 초과되거나 일시적으로
   불가능하면, **Then** 시스템은 재시도 가능한 분석 실패로 구분하고 답변 원문, Turn 순서와
   Coverage를 변경하지 않는다.
2. **Given** 분석 결과가 필수 항목 누락, 알 수 없는 값 또는 허용 길이 초과를 포함하고,
   **When** 결과를 검증하면, **Then** 시스템은 결과 전체를 거부하고 일부 Coverage 후보만
   사용하지 않는다.
3. **Given** 분석 결과가 답변에서 확인할 수 없는 주장이나 책의 사실을 의미 요약에 추가하고,
   **When** 결과를 검증하면, **Then** 시스템은 그 결과를 유효한 후속 처리 입력으로 확정하지
   않는다.
4. **Given** 같은 질문·답변·Coverage 입력을 결정적으로 재현하는 분석 대체 수단이고,
   **When** 반복 분석하면, **Then** 외부 연결 없이 동일한 정상 또는 오류 결과를 재현할 수 있다.

### 예외 상황

- 공백뿐이거나 확정되지 않은 답변, 답변이 없는 질문 Turn은 분석 대상으로 허용하지 않는다.
- 분석 대상 답변과 질문이 서로 다른 Turn에 속하거나 Interview의 Reading·Book 연결이 손상된
  경우에는 분석을 시작하지 않는다.
- 다른 사용자의 Interview나 답변은 존재 여부, 원문, 현재 Coverage 또는 분석 결과를 노출하지
  않는다.
- 현재 Coverage가 `PARTIAL` 또는 `COVERED`인 축을 답변이 같은 수준으로 다시 다루더라도 동일
  상태나 상태 하락 변경 후보를 만들지 않는다.
- 답변 하나가 여러 축을 뒷받침하면 여러 변경 후보를 반환할 수 있지만 같은 축을 중복해서
  반환하지 않는다.
- Coverage 후보의 근거 인용이 답변 원문에 그대로 존재하지 않으면 분석 결과 전체를 거부한다.
- 답변이 low-information이면 Coverage 변경 후보는 비어 있어야 한다. 반대로 후보가 하나도
  없다는 사실만으로 답변 전체가 반드시 low-information인 것은 아니다.
- 분석 요청 또는 결과에 사용자 입력을 명령으로 실행하거나 다른 사용자 데이터, 시스템 지침,
  비밀값 또는 내부 오류 정보를 노출하도록 요구하는 내용이 있어도 따르지 않는다.
- 분석 실패 후 같은 입력을 다시 처리하더라도 확정된 답변을 복제하거나 수정하지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 사용자 소유이며 Reading·Book 관계가 유효한 진행 중 Interview의 확정된
  답변만 분석 대상으로 허용해야 한다.
- **FR-002**: 분석 입력은 해당 Turn의 질문과 답변 원문, 현재 네 Core Coverage 상태, 그리고
  답변 해석에 필요한 신뢰된 Interview 맥락을 서로 구분해 포함해야 한다.
- **FR-003**: 시스템은 사용자 답변과 외부에서 유래한 내용은 신뢰할 수 없는 입력으로 취급하고,
  이 내용이 분석 규칙이나 권한 경계를 변경하는 지시로 사용되지 않게 해야 한다.
- **FR-004**: 분석 결과는 답변 의미 필드, low-information 여부, Core Coverage 변경 후보를
  항상 구분해 반환해야 하며, 답변 의미 필드는 정상 답변에서 핵심 의미를 가지고
  low-information 답변에서 `null`을 가져야 한다.
- **FR-005**: 답변의 핵심 의미는 답변 원문으로 직접 뒷받침되는 간결한 표현이어야 하며,
  사용자가 말하지 않은 신념·평가·해석, 확인되지 않은 책 내용 또는 새로운 사실을 추가해서는
  안 된다.
- **FR-006**: 시스템은 질문과 관련된 기억, 감정, 평가, 이유, 경험 연결 또는 읽은 뒤의 생각을
  구체화할 정보가 없는 답변을 low-information으로 판정해야 한다.
- **FR-007**: 시스템은 답변의 문자 수나 `잘 모르겠어요` 같은 특정 표현 하나만으로
  low-information을 판정해서는 안 되며, 짧더라도 구체적인 의미가 있으면 정상 답변으로
  구분해야 한다.
- **FR-008**: Coverage 변경 후보는 `MEMORY`, `REACTION`, `CONNECTION`, `AFTERTHOUGHT` 중
  답변이 직접 뒷받침하는 축만 포함하고, 각 후보에 해당 판정의 근거가 되는 답변 원문의 짧은
  인용을 연결해야 한다.
- **FR-009**: 각 Coverage 변경 후보는 `PARTIAL` 또는 `COVERED` 중 답변에서 드러난 정도에
  맞으면서 해당 축의 현재 상태보다 엄격히 높은 목표 상태를 가져야 하며 `UNCOVERED`, 알 수
  없는 상태, 현재와 같은 상태 또는 현재보다 낮은 상태를 제안해서는 안 된다.
- **FR-010**: `PARTIAL`은 관련 의미가 드러났지만 Reflection 근거로 사용하기 위해 구체화할
  여지가 있는 경우, `COVERED`는 답변만으로 해당 축의 의미와 근거를 충분히 보존할 수 있는
  경우에만 제안해야 한다.
- **FR-011**: low-information으로 판정된 결과는 `답변 의미`가 `null`이고 Coverage 변경 후보가
  빈 집합이어야 하며, 빈 문자열이나 low-information인 이유를 의미 값으로 대신 반환해서는 안
  된다.
- **FR-012**: 정상 답변이지만 어떤 축도 현재 Coverage보다 높이지 않거나 Core Coverage와 직접
  관련되지 않는 경우, 시스템은 low-information이 아닌 결과와 빈 Coverage 변경 후보를 함께
  반환해야 한다.
- **FR-013**: 분석 결과는 필수 항목, 값의 종류, 허용된 열거값, 중복 축, 길이 제한, 답변 근거와
  금지된 내용에 대해 후속 처리 전에 전체 단위로 검증되어야 한다.
- **FR-013A**: 각 Coverage 후보의 근거 인용은 분석 대상 답변 원문에 그대로 존재해야 하며,
  인용이 없거나 원문과 일치하지 않으면 해당 분석 결과 전체를 거부해야 한다.
- **FR-014**: 분석 결과의 일부라도 유효하지 않으면 시스템은 결과 전체를 거부해야 하며 유효해
  보이는 일부 의미나 Coverage 후보만 선택적으로 사용해서는 안 된다.
- **FR-015**: 분석 기능은 특정 외부 분석 제공자에 종속되지 않는 동일한 결과와 오류 경계를
  제공해야 하며, 외부 연결 없이 정상·low-information·오류 사례를 결정적으로 재현할 수 있어야
  한다.
- **FR-016**: 시스템은 분석 시간 초과, 일시적 이용 불가, 구성 오류와 유효하지 않은 결과를
  구분된 안전한 실패로 전달해야 하며, 외부 원문 오류·비밀값·내부 세부사항을 노출해서는 안 된다.
- **FR-017**: 답변 분석은 확정된 답변 원문, Turn 순서, Interview 상태, Coverage, Reading,
  Book Knowledge, Reflection 또는 Credit을 직접 변경해서는 안 된다.
- **FR-017A**: Bundle 07B는 유효하거나 실패한 분석 결과와 분석 시도를 Turn, Interview 또는
  별도 기록으로 영속 저장하지 않고 호출자에게 반환만 해야 한다.
- **FR-018**: 답변 분석에는 데이터 조회·수정, 웹 검색, 다른 사용자 데이터 접근, 관리자 기능
  또는 별도 도구를 실행할 권한을 부여해서는 안 된다.
- **FR-019**: 이번 기능은 Coverage 변경 후보의 실제 적용, Focus Coverage 생성·저장, 다음 질문
  또는 Feedback 생성, 질문 Budget, 반복 low-information 횟수 계산, Soft Stop, Interview 종료나
  Reflection 생성을 수행해서는 안 된다.

### 핵심 엔터티 *(기능에 데이터가 포함되는 경우 작성)*

- **답변 분석 입력**: 하나의 확정된 Interview Turn을 해석하는 데 필요한 질문, 사용자 답변,
  현재 Core Coverage와 신뢰된 맥락의 묶음이다. 사용자 답변과 신뢰된 정책 정보의 경계를
  유지한다.
- **답변 의미**: 사용자가 해당 답변에서 실제로 표현한 핵심 생각을 후속 질문이 참조할 수 있게
  간결하게 나타낸 값이다. 답변 밖의 사실이나 해석을 추가하지 않으며, low-information 답변에서는
  필드는 유지하되 값이 `null`이다.
- **Low-information 판정**: 해당 질문에 대한 의미 있는 기억·반응·연결·여운을 더 이상 추출할
  수 있는지 나타내는 단일 답변 수준의 판정이다. 연속 횟수나 종료 여부는 포함하지 않는다.
- **Coverage 변경 후보**: 답변이 직접 뒷받침하는 Core Coverage 축, 목표 상태와 답변 원문의
  짧은 근거 인용을 묶은 집합이다. 목표 상태는 해당 축의 현재 상태보다 엄격히 높아야 한다.
  상태 변경 명령이 아니라 검증 후 후속 흐름이 적용 여부를 결정할 제안이다.
- **답변 분석 결과**: 답변 의미, low-information 판정과 Coverage 변경 후보를 하나의 검증
  단위로 묶은 비영속 결과다. 일부만 유효한 결과는 전체가 무효이며, Bundle 07B에서는
  호출자에게 반환된 뒤 별도 기록으로 보존되지 않는다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 기억, 반응, 연결, 여운을 각각 단독 또는 복합으로 드러내는 대표 정상 답변 검증
  사례의 100%에서 답변이 뒷받침하는 Core Coverage 축만 변경 후보에 포함되고, 각 후보의 근거
  인용이 해당 답변 원문에서 확인되며 목표 상태가 현재 상태보다 높다.
- **SC-002**: 명시적인 무내용·회피성 답변과 짧지만 구체적인 답변을 포함한 경계 사례의 100%에서
  두 유형이 기대한 low-information 여부로 구분된다.
- **SC-003**: 정상 분석 결과의 100%에서 의미 요약의 각 내용은 사용자 답변에서 근거를 찾을 수
  있고, 사용자가 말하지 않은 신념·평가·사실은 포함되지 않는다.
- **SC-004**: 필수 항목 누락, 알 수 없는 축·상태, 중복 축, 누락되거나 원문과 일치하지 않는
  근거 인용, low-information과 모순되는 비어 있지 않은 의미 또는 Coverage 후보, 허용 길이
  초과와 금지된 내용을 포함한 대표 오류 사례의 100%가 후속 처리 전에 전체 거부된다.
- **SC-005**: 시간 초과, 일시 장애, 구성 오류와 유효하지 않은 결과 사례의 100%에서 이미 확정된
  답변, Turn 순서, Interview 상태와 Coverage가 변경되지 않고 민감한 내부 정보가 노출되지 않는다.
- **SC-006**: 외부 연결이 없는 대표 검증 세트에서 정상 답변, low-information 답변과 각 오류
  유형을 100% 재현할 수 있다.
- **SC-007**: 다른 사용자 또는 관계가 손상된 Interview를 대상으로 한 검증 사례의 100%에서
  답변·Coverage·분석 결과와 대상 존재 여부가 노출되지 않는다.

## 가정

- Bundle 06A에서 질문과 최대 2,000자의 사용자 답변이 하나의 Turn에 이미 안전하게 확정되어
  있으며, 분석 실패는 이 원본 기록의 저장 성공을 되돌리지 않는다.
- Bundle 07A에서 네 Core Coverage 축과 `UNCOVERED`/`PARTIAL`/`COVERED` 상태, 단방향 patch
  적용 계약이 이미 제공된다.
- Bundle 07B는 한 답변에 대한 분석 계약과 검증 경계까지만 제공한다. 분석 호출을 답변 저장
  흐름에 연결하고 Coverage 후보를 실제 적용하는 작업은 Bundle 07C의 Interview Step 통합에서
  수행한다.
- low-information은 한 답변에 대한 판정이다. 연속 횟수 집계와 조기 종료 기준은 Bundle 08A가
  담당한다.
- Focus Coverage 발견과 우선순위화는 적응형 다음 질문 정책과 함께 후속 범위에서 다루며,
  이번 기능은 Bundle 07A의 네 Core Coverage에 대한 후보만 반환한다.
- 분석 결과는 사용자에게 직접 표시되는 완성 문구가 아니다. 의미 확인 Feedback과 다음 질문의
  문장·화면은 Bundle 07C 이후 범위다.
- 실제 분석 제공자나 모델 선택과 구체적인 제한값은 계획 단계에서 기존 질문 생성 경계와
  프로젝트 설정을 근거로 결정한다. 분석 결과를 후속 Bundle에서 영속할 필요가 생기면 해당
  Bundle의 상태 전이와 원자성 계약으로 별도 명세한다.
- 이번 명세의 검증은 외부 network나 credential 없이 결정적인 계약·정책 사례로 수행하며,
  별도 요청이 없는 실제 브라우저 검증은 완료 조건에 포함하지 않는다.
