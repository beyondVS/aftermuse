# Bundle 07C — 적응형 다음 Turn 구현 계획

## 목표와 경계

확정된 답변을 분석하고 Coverage를 반영해 다음 질문을 이어간다. 추가 질문의 근거가 없으면 검증된 질문 생략을 기록한다. 답변 원문은 후속 처리 실패와 관계없이 보존한다. Focus Coverage, 질문 수 제한, Soft Stop, Reflection, 이전 Turn 열람 및 Day 08의 상세 오류 UX는 포함하지 않는다.

## 구현 순서

1. `InterviewTurn`에 nullable 질문 생략 완료 표식을 추가한다. 기존 행의 `NULL`은 미처리 상태로 유지한다. 질문 생성 결과는 단일 질문 또는 명시적 생략 제안으로 구분하고, fake·OpenAI Adapter와 설정을 확장한다. Provider는 상태를 변경하지 않는다.
2. 확정 답변, 관련 이전 Turn, 분석 의미, low-information 여부, 적용 예정 Coverage와 허용된 Book·Reading 맥락으로 다음 질문 입력을 구성한다. 질문은 한 문장·300자 이하이며 답변이나 확인된 맥락에 근거해야 한다. 생략 제안은 네 축이 모두 `COVERED`이고 사유가 유효할 때만 시스템이 수락한다. 빈 결과는 생략으로 취급하지 않는다.
3. 첫 Turn 전용 답변 저장을 여러 Turn으로 일반화하되 기존 첫 답변 경로는 유지한다. 답변을 먼저 확정하고 트랜잭션 밖에서 분석·생성한 뒤 Interview를 잠가 최신 상태를 재검증한다. Coverage와 다음 Turn 또는 생략 표식을 한 트랜잭션에서 확정한다. 중복 요청은 확정된 결과를 재사용하고 오래된 제안은 적용하지 않는다.
4. 현재 마지막 Turn만 질문·답변 대상으로 표시한다. 답변 저장 후 준비 상태를 보여주고 성공하면 새 질문 하나로 전환한다. 실패 시 답변 보존 사실과 최소 재시도 행동을 제공한다. 질문 생략은 실패와 구별한다. 일반 POST와 HTMX를 지원한다.

## 검증

- fake Provider로 답변 내용·Coverage·low-information에 따른 질문 변화와 근거 없는 책 내용 거부를 검증한다.
- PostgreSQL에서 3회 답변→4번째 질문, 생략 시 Coverage·표식 확정, 분석·생성·저장 실패 시 부분 반영 방지, 동시 요청의 Turn 중복 방지를 검증한다.
- 소유권, 재접속, 기존 첫 Turn 경로, 일반 POST·HTMX 상태 전이를 회귀 검증한다. 마이그레이션 SQL과 적용·역적용을 확인하고 `uv run python scripts/verify.py`를 실행한다.
- 구현이 안정되면 README, CHANGELOG와 Day 07 완료 상태를 실제 검증 결과에 맞춰 갱신한다.

기존 30초 Provider timeout과 자격 증명 없는 fake 테스트를 재사용한다. 실제 브라우저와 외부 LLM live 호출은 완료 조건에 포함하지 않는다.
