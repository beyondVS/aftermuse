# 기능 사양: 적응형 다음 Turn

**기능 브랜치**: `feature/day-07-adaptive-interview-loop`

**생성일**: 2026-09-13

**상태**: 초안

**입력**: 사용자 설명: "7일차 구현 계획 중 `Bundle 07C — 적응형 다음 Turn`의 명세"

## Clarifications

### Session 2026-09-13

- Q: 네 Core Coverage가 모두 `COVERED`이고 답변에서 더 물을 근거도 없을 때, 07C는 다음 질문을 어떻게 처리해야 하나요? → A: 다음 질문을 생성하지 않고 답변을 보존한 채 Day 08의 종료 정책을 기다린다.
- Q: 마지막 답변의 분석으로 네 Coverage가 모두 `COVERED`가 되어 다음 질문을 만들지 않는 경우, 그 답변의 Coverage 변경은 저장해야 하나요? → A: 검증된 Coverage 상승은 저장하고 다음 질문 Turn은 만들지 않는다.
- Q: 모든 Core Coverage가 `COVERED`일 때 ‘더 물을 근거가 없다’는 판단은 어떻게 내려야 하나요? → A: 질문 생성기가 근거 없음 여부를 제안하고, 시스템이 Coverage와 제안의 유효성을 검증한 뒤 새 Turn 생성 여부를 결정한다.
- Q: 답변 뒤에 다음 질문이 없는 상태가 ‘검증된 질문 생략’인지 ‘질문 생성 실패’인지, 화면을 다시 열거나 Day 08 종료 정책이 실행될 때 어떻게 구분해야 하나요? → A: 답변 Turn에 검증된 질문 생략 결과를 명시적으로 기록한다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 내 답변을 반영한 다음 질문 받기 (우선순위: P1)

사용자는 방금 남긴 답변에서 드러난 생각을 바탕으로, 아직 더 이야기할 가치가 있는 방향을 묻는 다음 질문을 받는다. 질문은 정해진 목록을 순서대로 읽지 않고 사용자의 표현과 현재까지의 Coverage를 함께 고려한다.

**우선순위가 높은 이유**: 답변 기반 질문은 고정 설문과 구별되는 Interview의 핵심 경험이다.

**독립 테스트**: 같은 첫 질문에 서로 다른 구체적 답변을 제공하거나 현재 Coverage를 바꾸어 다음 질문을 만들고, 질문의 근거와 선택한 방향이 각 입력에 맞는지 확인한다.

**인수 시나리오**:

1. **Given** 사용자가 한 장면을 기억하지만 왜 남았는지는 설명하지 않았고 `MEMORY`가 `PARTIAL`인 경우, **When** 다음 질문을 만들면, **Then** 그 장면에 대한 사용자의 표현을 이어받아 이유를 묻는 질문을 제안한다.
2. **Given** 사용자가 반응의 이유까지 충분히 설명해 `REACTION`이 `COVERED`이고 다른 Core Coverage에 공백이 있는 경우, **When** 다음 질문을 만들면, **Then** 이미 충분히 다룬 반응을 되풀이하지 않고 답변에서 연결 가능한 공백을 우선한다.
3. **Given** 답변이 low-information인 경우, **When** 다음 질문을 만들면, **Then** 없는 생각을 추측하거나 같은 주제를 압박하지 않고 다른 열린 방향으로 전환할 수 있다.
4. **Given** 책 정보가 제한된 Interview인 경우, **When** 다음 질문을 만들면, **Then** 확인되지 않은 책 내용은 전제하지 않고 사용자의 기억과 표현에서 출발한다.
5. **Given** 직전 답변의 분석을 반영하면 네 Core Coverage가 모두 `COVERED`가 되고 질문 생성기가 더 물을 근거가 없다고 유효하게 제안한 경우, **When** 시스템이 제안을 검증하면, **Then** 검증된 Coverage 상승과 해당 답변 Turn의 질문 생략 결과를 확정하되 새 질문 Turn은 생성하지 않고 Day 08의 종료 정책을 기다린다.

---

### 사용자 스토리 2 - 답변부터 다음 Turn까지 끊김 없이 이어가기 (우선순위: P1)

사용자는 답변을 제출한 뒤 자신의 원문이 먼저 보존되고, 분석과 Coverage 반영을 거쳐 더 물을 근거가 있는 동안 다음 질문 하나가 현재 Interview에 이어지는 경험을 한다. 이 과정을 반복해 최소 세 번의 Turn에 답할 수 있다.

**우선순위가 높은 이유**: 질문 품질만 좋아도 답변·Coverage·Turn이 서로 어긋나면 사용자의 생각이 이어지는 경험을 제공할 수 없다.

**독립 테스트**: 첫 질문부터 세 차례 답변을 순서대로 제출하고, 각 답변 원문과 Coverage, 새 질문의 순서·근거가 일치하는지 확인한다.

**인수 시나리오**:

1. **Given** 진행 중 Interview에 답변하지 않은 현재 질문이 있고 후속 질문의 근거가 남아 있는 경우, **When** 사용자가 답변을 제출하면, **Then** 원문이 해당 Turn에 한 번 확정된 후 그 답변의 분석 결과로 Coverage가 갱신되고 다음 질문 Turn 하나가 순서대로 확정된다.
2. **Given** 두 Turn의 답변이 확정되고 다음 질문이 준비된 경우, **When** 세 번째 질문에도 답하면, **Then** 세 답변과 질문의 순서가 보존되고 네 번째 질문이 이전 답변과 현재 Coverage를 반영한다.
3. **Given** 같은 답변 제출 또는 다음 단계 요청이 반복·동시에 도착한 경우, **When** 처리가 끝나면, **Then** 최초 답변 원문과 각 순서의 질문은 하나씩만 남고 Coverage는 하락하지 않는다.

---

### 사용자 스토리 3 - 후속 처리 실패에도 기록 보존하기 (우선순위: P2)

사용자는 분석이나 질문 생성에 문제가 생겨도 이미 작성한 답변을 잃지 않는다. 불완전한 질문이나 일부만 반영된 후속 상태가 다음 질문으로 보이지 않는다.

**우선순위가 높은 이유**: 외부 분석·생성 오류가 사용자 원문과 Interview의 일관성을 훼손해서는 안 된다.

**독립 테스트**: 답변 확정 직후 분석 실패, 질문 생성 시간 초과·무효 결과, 질문 저장 실패를 각각 재현하고 확정 기록·Coverage·Turn 수를 확인한다.

**인수 시나리오**:

1. **Given** 답변은 저장되었지만 분석에 실패한 경우, **When** 현재 Interview를 다시 확인하면, **Then** 답변 원문은 유지되고 Coverage와 다음 질문은 확정되지 않는다.
2. **Given** 분석은 유효하지만 다음 질문 생성 또는 저장에 실패한 경우, **When** 처리가 끝나면, **Then** 답변 원문은 유지되고 해당 답변에 대한 Coverage 반영과 다음 Turn은 함께 미확정 상태로 남는다.
3. **Given** 실패한 후속 처리를 같은 확정 답변으로 다시 실행해 유효한 결과를 얻은 경우, **When** 처리가 끝나면, **Then** 답변을 다시 쓰지 않고 Coverage와 다음 질문 하나가 확정된다.
4. **Given** 검증된 질문 생략으로 다음 Turn이 없는 Interview인 경우, **When** 사용자가 화면을 다시 열면, **Then** 생성 실패로 오인해 같은 답변을 재처리하지 않고 기록된 질문 생략 상태를 유지한다.

### 예외 상황

- 공백 답변, 미확정 질문, 완료된 Interview 또는 손상된 Reading·Book 연결에서는 다음 단계를 진행하지 않는다.
- 다른 사용자의 Interview·답변·Coverage·질문과 대상 존재 여부를 노출하지 않는다.
- 답변이 어떤 Core Coverage도 높이지 않더라도 정상 답변이면 현재 공백과 답변 맥락을 바탕으로 다음 질문을 만들 수 있다.
- low-information 답변에서는 의미 요약이나 Coverage 상승을 꾸며내지 않는다.
- 네 Core Coverage가 모두 `COVERED`여도 답변에 근거한 구체적인 후속 탐색이 남아 있다면 다음 질문을 만들 수 있다. 둘 다 없으면 질문을 억지로 만들지 않는다.
- 추가 질문이 필요 없다는 유효한 판단과 분석·생성 실패를 구분한다. 전자에서는 검증된 Coverage 상승을 보존하고, 후자에서는 해당 답변의 Coverage 상승을 미확정 상태로 둔다.
- 질문 생략 결과가 기록된 답변은 반복 요청에서도 새 질문을 생성하거나 생략 결정을 덮어쓰지 않는다.
- 질문 생성기의 빈 내용·형식 오류·근거 없는 질문 생략 제안은 정상적인 ‘더 물을 근거가 없음’으로 간주하지 않는다.
- 질문 제안이 비어 있거나 여러 질문을 담거나 길이·근거·내용 규칙을 위반하면 저장하거나 노출하지 않는다.
- 검증된 질문을 저장하기 직전 다른 요청이 다음 Turn을 확정했다면 기존 Turn을 사용하고 중복 질문을 만들지 않는다.
- 사용자 입력이나 외부 콘텐츠에 상태 변경·비밀 공개 지시가 있더라도 질문 내용의 자료로만 취급한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 사용자 소유이며 Reading·Book 관계가 유효한 진행 중 Interview에서 답변 가능한 현재 질문의 최초 제출 또는 답변이 확정됐지만 후속 처리가 실패한 질문의 재시도에 대해서만 다음 단계를 허용해야 한다.
- **FR-002**: 시스템은 답변 원문을 분석·Coverage 변경·질문 생성보다 먼저 확정해야 하며 후속 실패로 원문을 되돌리거나 교체해서는 안 된다.
- **FR-003**: 시스템은 해당 질문과 확정 답변, 이전에 확정된 관련 Turn, 현재 네 Core Coverage, 허용된 Book·Reading 맥락을 다음 질문 판단에 사용해야 한다.
- **FR-004**: 시스템은 Bundle 07B의 유효한 분석 결과에서만 답변 의미, low-information 판정과 Coverage 상승 후보를 받아야 한다. 분석 실패나 무효 결과를 부분적으로 사용해서는 안 된다.
- **FR-005**: 시스템은 Coverage 후보를 해당 Interview에만 적용해야 한다. 다음 질문이 필요한 경우 그 질문의 근거가 된 Coverage 변경과 새 Turn을 함께 확정하고, 질문 확정이 실패하면 해당 답변의 Coverage 변경은 남기지 않아야 한다.
- **FR-006**: 다음 질문은 방금 확정된 답변의 구체적 내용과 적용 후 Coverage를 반영하고, 이미 충분히 다룬 축의 반복보다 답변에서 확장 가능한 미충족 축을 우선해야 한다.
- **FR-007**: 시스템은 답변에 근거한 후속 탐색이 어려운 경우 다른 미충족 Core Coverage로 전환할 수 있어야 하며, low-information 답변을 근거 없는 의미나 Coverage로 바꾸어서는 안 된다.
- **FR-007A**: 유효한 분석 결과를 반영한 뒤 네 Core Coverage가 모두 `COVERED`이고 질문 생성기가 답변에서 더 물을 구체적인 근거가 없다고 유효하게 제안하면, 시스템은 이 조건을 직접 검증한 뒤 Coverage 상승과 해당 답변 Turn의 질문 생략 결과를 함께 확정하고 새 질문 Turn 없이 후속 종료 정책을 기다려야 한다. 그 상태만으로 이 Bundle에서 Interview를 종료해서는 안 된다.
- **FR-008**: 질문은 한 번에 하나의 열린 질문이어야 하며, 300자 이하이고 사용자에게 답변 밖의 신념·해석·평가 또는 확인되지 않은 책 사실을 전제해서는 안 된다.
- **FR-009**: `READY_LIMITED` Interview에서는 확인되지 않은 책 내용을 질문의 사실 전제로 사용해서는 안 되며, `READY`에서도 확인된 정보보다 사용자 자신의 답변을 우선해야 한다.
- **FR-010**: 질문 생성 결과는 단일 질문 또는 더 물을 근거가 없다는 명시적 제안 중 하나로 구분되어야 한다. 질문 제안은 필수 내용, 한 질문 여부, 길이, 허용된 맥락과 금지된 내용을, 질문 생략 제안은 네 Core Coverage가 모두 `COVERED`이고 답변에 근거한 후속 탐색이 없다는 사유를 검증해야 한다. 비어 있거나 유효하지 않은 결과는 전체 거부해야 한다.
- **FR-011**: 질문 생성기는 질문이나 질문 생략을 제안할 수 있지만 Interview, 답변, Coverage, Turn 또는 사용자 권한을 직접 변경하거나 질문 생략을 최종 결정할 수 없어야 한다. 상태 변경은 검증된 결과에 따라 신뢰된 Interview 흐름에서만 이루어져야 한다.
- **FR-012**: 같은 답변에 대한 반복·동시 처리에서는 답변 원문을 변경하지 않고 다음 Turn을 최대 하나만 확정하며, Turn 순서를 건너뛰거나 Coverage를 하락시키지 않아야 한다.
- **FR-013**: 분석 실패, 생성 실패·시간 초과, 무효 질문 또는 저장 실패 시 답변 원문과 이전에 확정된 Turn·Coverage를 유지하고 미완성 질문을 노출하지 않아야 한다.
- **FR-014**: 실패한 후속 처리는 같은 확정 답변을 바탕으로 다시 시도할 수 있어야 하며, 이미 다음 Turn이 확정되었다면 그것을 재사용해야 한다.
- **FR-014A**: 시스템은 해당 답변 Turn에 검증된 질문 생략 결과가 기록되어 있으면 생성 실패와 구별하여 재접속·반복 요청에도 재분석하거나 다음 질문을 생성하지 않아야 한다.
- **FR-015**: 사용자는 현재 질문, 답변 보존 이후 다음 질문 준비, 검증된 질문 생략 상태를 구분할 수 있어야 하며, 준비 중이거나 질문이 생략된 상태에서는 새 답변을 중복 제출하게 해서는 안 된다.
- **FR-016**: 이번 기능은 네 Core Coverage와 답변 기반 다음 질문의 연결에 한정하며 Focus Coverage 영속화, 질문 Budget·Safety Cap, Soft Stop, 반복 low-information 종료, 이전 Turn 열람, Reflection 및 Credit 변경을 수행해서는 안 된다.

### 핵심 엔터티 *(기능에 데이터가 포함되는 경우 작성)*

- **Interview Turn**: 한 Interview에서 순서가 정해진 질문과 한 번 확정되는 사용자 답변이다. 새 Turn은 직전 확정 답변의 후속 질문 하나를 담으며, 답변 뒤에 질문을 생략하기로 검증된 경우 그 결과는 해당 답변 Turn에 남는다.
- **Core Coverage**: `MEMORY`, `REACTION`, `CONNECTION`, `AFTERTHOUGHT`별 현재 상태다. 다음 질문이 필요한 경우 새 Turn과 함께 상승하고, 더 물을 근거가 없어 질문을 만들지 않는 경우 검증된 상승만 확정한다.
- **다음 질문 제안**: 확정 답변과 현재 Coverage를 근거로 제안된 단일 질문 또는 추가 질문의 근거가 없다는 명시적 판단 후보다. 검증 전에는 사용자에게 보이거나 Interview 상태가 되지 않는다.
- **Interview Step**: 답변 원문 확정 후 분석과 Coverage 반영을 거쳐 다음 Turn 확정 또는 검증된 질문 생략으로 이어지는 사용자 관점의 한 단계다. 답변의 보존은 후속 처리의 성공과 독립적이다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 구체적인 기억·반응·연결·여운 답변을 포함한 대표 사례의 100%에서 다음 질문은 해당 답변에 근거하고, 이미 충분히 다룬 축을 불필요하게 반복하지 않는다.
- **SC-002**: 추가 질문의 근거 또는 미충족 Core Coverage가 남아 있는 정상 답변, Coverage 후보가 없는 답변, low-information 답변의 대표 흐름 100%에서 사용자는 최소 세 Turn에 순서대로 답변하고 네 번째 질문을 받을 수 있다.
- **SC-003**: 사용자에게 노출되는 다음 질문의 100%가 단일 열린 질문·300자 이하·허용된 근거 조건을 충족한다. `READY_LIMITED` 사례에서는 확인되지 않은 책 사실을 전제한 질문이 0건이다.
- **SC-003A**: 직전 답변을 반영하면 네 Core Coverage가 모두 `COVERED`이고 검증 가능한 질문 생략 제안이 있는 대표 사례 100%에서 Coverage 상승과 답변 Turn의 생략 결과가 보존되고 새 Turn은 0건이다. 빈 결과나 유효하지 않은 생략 제안은 이 상태로 처리되지 않는다.
- **SC-003B**: 검증된 질문 생략과 질문 생성 실패 후 재접속·반복 요청하는 대표 사례 100%에서 두 상태가 구별되고, 생략된 질문의 재생성이나 실패 상태의 완료 오인이 0건이다.
- **SC-004**: 분석·생성·저장 실패와 반복·동시 요청의 대표 사례 100%에서 이미 확정된 답변이 한 번만 보존되고, 부분 Coverage 변경이나 중복 다음 Turn이 0건이다.
- **SC-005**: 후속 처리 실패 후 다시 시도하는 대표 사례 100%에서 답변 재입력 없이 다음 질문 하나를 받을 수 있다.
- **SC-006**: 다른 사용자 또는 유효하지 않은 Interview 접근 사례 100%에서 질문·답변·Coverage와 대상 존재 여부가 노출되지 않는다.

## 가정

- Bundle 06A에서 질문 Turn과 최대 2,000자의 답변 원문을 한 번 확정하는 계약이 제공된다.
- Bundle 07A는 네 Core Coverage의 단방향 상태 전환을, Bundle 07B는 답변 의미·low-information·상승 후보의 검증된 비영속 결과를 제공한다.
- 이 단계는 답변 내용과 네 Core Coverage만으로 다음 질문을 고른다. Focus Coverage의 별도 상태 모델과 우선순위화는 이 Bundle의 완료 조건이 아니다.
- 질문의 목표 수와 종료 선택은 Day 08의 정책이다. 이 명세의 최소 세 Turn은 계속 질문할 근거가 있는 정상 흐름의 검증 기준이며 모든 Interview의 최소 질문 수나 무제한 질문을 제품 정책으로 확정하지 않는다.
- 네 Core Coverage가 모두 `COVERED`이고 추가 질문의 근거가 없으면 다음 질문 없이 Day 08의 종료 정책을 기다린다. 이는 종료나 Reflection 생성을 07C에 앞당기는 결정이 아니다.
- Day 08의 오류/재시도 UX는 상세 화면 문구와 복구 동선을 완성한다. 이 단계에서는 답변 보존, 안전한 재시도 가능 상태와 현재 질문 표시를 보장한다.
- 별도 요청이 없는 실제 브라우저 검증은 완료 조건에 포함하지 않는다.
