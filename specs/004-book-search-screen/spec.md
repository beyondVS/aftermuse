# 기능 사양: 도서 검색 화면

**기능 브랜치**: `feature/day-02-auth-book-search`

**생성일**: 2026-09-03

**상태**: 초안

**입력**: 사용자 설명: "2일차 작업의 IMP-023 도서 검색 화면을 구현하기 위한 명세"

## Clarifications

### Session 2026-09-03

- Q: 한 번의 검색에서 결과가 많을 때 화면은 결과를 어떻게 제공해야 합니까? → A: Provider가 반환한 결과를 한 목록에 모두 표시하고 별도 페이지 이동은 제공하지 않는다.
- Q: 사용자가 입력할 수 있는 검색어의 최대 길이와 초과 시 동작을 어떻게 정할까요? → A: 최대 200자이며, 초과하면 외부 검색 없이 입력 오류를 표시한다.
- Q: 새 검색이 시작되면 이전 검색 결과를 화면에서 어떻게 처리해야 합니까? → A: 이전 결과를 즉시 숨기고 Loading 안내만 표시한다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 올바른 판본 찾기 (우선순위: P1)

로그인한 사용자는 제목이나 저자 등 기억하는 검색어를 입력하고, 표지를 중심으로 정리된
결과에서 같은 이름의 책과 서로 다른 판본을 구분할 수 있다.

**우선순위가 높은 이유**: 사용자가 올바른 책을 식별해야 이후 도서 선택과 독서 기록
흐름을 신뢰할 수 있다.

**독립 테스트**: 같은 제목이지만 표지, 저자, 출판사 또는 출간연도가 다른 결과를 준비해
검색하고, 검색어와 결과 목록 및 판본 구분 정보가 화면에 정확히 나타나는지 확인한다.

**인수 시나리오**:

1. **Given** 로그인한 사용자가 검색 화면에 있고, **When** 유효한 검색어로 검색하면,
   **Then** 해당 검색어와 일치하는 도서가 표지 기반 결과 목록으로 표시된다.
2. **Given** 같은 제목의 여러 판본이 검색 결과에 있고, **When** 사용자가 결과를
   비교하면, **Then** 표지, 제목, 저자, 출판사와 출간연도로 각 판본을 구분할 수 있다.
3. **Given** 선택 서지정보가 없는 결과가 있고, **When** 목록을 확인하면, **Then** 존재하지
   않는 정보를 추측해 표시하지 않으면서 제목과 식별 가능한 정보는 유지된다.

---

### 사용자 스토리 2 - 검색 진행과 결과 상태 이해 (우선순위: P1)

사용자는 검색 전, 검색 중, 결과 없음 및 검색 실패 상태를 명확히 구분하고 실패 시 같은
검색어로 다시 시도할 수 있다.

**우선순위가 높은 이유**: 상태 안내가 없으면 사용자는 검색이 진행 중인지, 책이 없는지,
일시적으로 실패했는지 판단할 수 없다.

**독립 테스트**: 초기 화면, 진행 중인 검색, 정상 빈 결과와 검색 실패를 각각 재현해 상태별
안내와 가능한 다음 행동이 혼동 없이 제공되는지 확인한다.

**인수 시나리오**:

1. **Given** 아직 검색하지 않은 초기 화면에서, **When** 사용자가 화면을 확인하면,
   **Then** 검색 입력과 실행 방법은 보이되 결과 없음이나 오류 안내는 표시되지 않는다.
2. **Given** 이전 검색 결과가 표시되어 있고, **When** 새 유효 검색이 시작되면, **Then**
   이전 결과는 즉시 숨겨지고 검색이 끝날 때까지 Loading 안내만 표시된다.
3. **Given** 검색은 정상적으로 끝났지만 일치하는 책이 없고, **When** 결과가 표시되면,
   **Then** 오류와 구분되는 빈 결과 안내와 검색어를 바꿔볼 수 있는 안내가 나타난다.
4. **Given** 검색 제공자의 문제로 검색에 실패했고, **When** 결과가 표시되면, **Then**
   기술적인 오류 상세 없이 실패 안내와 다시 시도할 수 있는 행동이 나타난다.
5. **Given** 사용자가 빈 문자열, 공백만 있는 문자열 또는 200자를 초과한 검색어를
   입력했고, **When** 검색을 시도하면, **Then** 외부 검색을 시작하지 않고 유효한 검색어
   입력이 필요함을 알 수 있다.

---

### 사용자 스토리 3 - 기기와 입력 방식에 관계없이 검색 (우선순위: P2)

사용자는 Desktop과 Mobile 화면에서 키보드, 포인터 또는 보조 기술을 사용해 검색하고 결과
상태와 도서 정보를 확인할 수 있다.

**우선순위가 높은 이유**: 도서 검색은 핵심 흐름의 입구이므로 화면 크기나 입력 방식 때문에
진입이 막히면 안 된다.

**독립 테스트**: 대표 Desktop과 Mobile 크기에서 긴 제목과 여러 저자를 포함한 결과를
표시하고, 키보드만으로 입력·검색·재시도에 접근하며 모든 상태가 색상 외 정보로도
구분되는지 확인한다.

**인수 시나리오**:

1. **Given** 긴 제목과 여러 저자가 포함된 검색 결과가 있고, **When** Desktop 또는 Mobile
   화면에서 확인하면, **Then** 가로 스크롤 없이 핵심 서지정보를 읽고 결과를 구분할 수 있다.
2. **Given** 키보드만 사용하는 사용자가 있고, **When** 검색 입력부터 검색 실행과 재시도
   행동까지 이동하면, **Then** 논리적인 순서와 명확한 초점 표시로 모두 조작할 수 있다.
3. **Given** 보조 기술을 사용하는 사용자가 있고, **When** 검색 상태가 바뀌면, **Then**
   Loading, Empty, Error 및 결과 상태를 텍스트와 의미 있는 이름으로 파악할 수 있다.

### 예외 상황

- 표지 정보가 없거나 표지를 불러오지 못해도 결과의 레이아웃과 도서 식별 정보는 유지한다.
- 제목이나 저자명이 길거나 저자가 여러 명이어도 다른 결과의 정보와 겹치지 않아야 한다.
- 출간일이 있으면 출간연도를 파생해 보여주고, 출간일이 없으면 연도를 추측하지 않는다.
- 사용자가 연속으로 검색할 때 새 검색이 시작되면 이전 결과를 즉시 숨기고 Loading 안내만
  표시해야 한다.
- 검색어가 200자를 초과하면 외부 검색 없이 입력 오류를 표시하고 사용자가 입력을 수정할 수
  있어야 한다.
- 검색 실패 안내에는 자격 증명, 제공자 응답 본문, 예외 이름이나 내부 진단 정보가 나타나지
  않아야 한다.
- 인증되지 않은 사용자는 비공개 도서 검색 화면과 검색 결과에 접근할 수 없어야 한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 로그인한 사용자가 도서 검색 화면에 접근할 수 있게 해야 한다.
- **FR-002**: 시스템은 검색어를 입력하고 명시적으로 검색을 실행할 수 있는 이름 있는 입력과
  행동을 제공해야 한다.
- **FR-003**: 시스템은 사용자가 실행한 검색어를 검색 결과와 함께 유지해 현재 결과의 기준을
  알 수 있게 해야 한다.
- **FR-004**: 시스템은 양끝 공백을 제거한 검색어가 1자 이상 200자 이하일 때만 외부
  검색을 시작하고, 이 범위를 벗어나면 입력 오류를 표시해야 한다.
- **FR-005**: 시스템은 검색 처리 중임을 텍스트로 알 수 있는 Loading 상태를 제공해야 한다.
- **FR-006**: 시스템은 Provider가 반환한 정상 결과 전체를 별도 페이지 이동 없이 하나의
  표지 중심 목록으로 표시해야 한다.
- **FR-007**: 각 검색 결과는 제목을 필수로 표시하고, 제공된 경우 표지, 저자, 출판사와
  출간연도를 함께 표시해야 한다.
- **FR-008**: 시스템은 전체 출간일에서 출간연도만 표시하되 원본 값이 없으면 연도를
  추측해서는 안 된다.
- **FR-009**: 시스템은 검색 결과를 제공된 순서대로 표시하고 선택 서지정보를 임의로
  보완해서는 안 된다.
- **FR-010**: 시스템은 검색 결과가 없을 때 오류와 구분되는 Empty 상태와 검색어 변경
  안내를 제공해야 한다.
- **FR-011**: 시스템은 검색에 실패할 때 Empty 상태와 구분되는 Error 상태와 같은 검색을
  다시 시도할 수 있는 행동을 제공해야 한다.
- **FR-012**: Error 상태는 자격 증명, 원본 오류 본문, 예외 이름 및 내부 진단 정보를
  노출해서는 안 된다.
- **FR-013**: 초기 Normal 상태는 검색 전임을 나타내며 Empty 또는 Error 메시지를 미리
  표시해서는 안 된다.
- **FR-014**: 시스템은 새 검색이 시작되면 이전 결과를 즉시 숨기고 새 결과가 준비될 때까지
  Loading 상태만 표시해야 한다.
- **FR-015**: 모든 검색 입력, 실행 및 재시도 행동은 키보드로 접근 가능하고 명확한 초점
  표시와 의미 있는 이름을 가져야 한다.
- **FR-016**: Loading, Empty, Error 및 정상 결과는 색상에만 의존하지 않고 텍스트나 구조로
  구분되어야 한다.
- **FR-017**: Desktop과 Mobile에서 검색 입력, 상태 안내 및 결과가 가로 스크롤 없이 읽고
  조작할 수 있게 배치되어야 한다.
- **FR-018**: 표지가 없거나 표시되지 않아도 대체 표현과 나머지 서지정보로 결과를 이해할 수
  있어야 한다.
- **FR-019**: 인증되지 않은 사용자는 검색 화면이나 검색 결과를 열람할 수 없어야 한다.
- **FR-020**: 이번 기능은 검색 결과를 저장하거나 도서를 선택·등록하거나 Reading을
  생성하거나 Book Knowledge 준비를 시작해서는 안 된다.

### 핵심 엔터티

- **검색 화면 상태**: 검색 전, 검색 중, 정상 결과, 빈 결과 또는 오류 중 현재 사용자에게
  표시되는 한 가지 상태를 나타낸다.
- **검색어**: 사용자가 입력하고 현재 결과의 기준으로 확인할 수 있는 문자열이다.
- **표시용 도서 결과**: 제목과 ISBN13으로 식별되며, 제공된 표지, 저자, 출판사 및 전체
  출간일에서 파생한 출간연도를 사용자가 판본 구분에 활용하는 항목이다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 준비된 정상 검색 시나리오의 100%에서 사용자가 검색을 실행하고 결과 목록을
  확인할 수 있다.
- **SC-002**: 같은 제목의 판본 구분 시나리오의 100%에서 표지, 저자, 출판사 또는
  출간연도 중 제공된 정보로 결과를 구분할 수 있다.
- **SC-003**: 초기, Loading, Empty, Error 및 정상 결과 시나리오의 100%가 서로 다른 안내와
  가능한 다음 행동을 제공한다.
- **SC-004**: 검색 응답이 준비된 뒤 1초 이내에 해당 결과 또는 상태가 사용자에게 표시된다.
- **SC-005**: 너비 375px Mobile과 1280px Desktop 검증에서 검색 입력, 상태 및 결과의
  가로 페이지 스크롤이 0건이다.
- **SC-006**: 키보드 검증의 100%에서 검색 입력, 검색 실행 및 재시도에 논리적인 순서로
  접근하고 현재 초점을 식별할 수 있다.
- **SC-007**: 모든 상태 검증에서 상태를 색상만으로 구분하는 경우와 민감하거나 내부적인
  오류 상세 노출이 각각 0건이다.
- **SC-008**: 이 기능의 검색 시나리오에서 도서 저장, Reading 생성 및 Book Knowledge 준비
  시작은 모두 0건이다.
- **SC-009**: 빈 문자열, 공백만 있는 문자열 및 200자를 초과한 검색어 검증에서 외부 검색
  요청은 0건이며 입력 오류가 표시된다.

## 가정

- IMP-004의 공통 Responsive Web 토대와 IMP-010의 기존 로그인 흐름을 재사용한다.
- IMP-022가 제공하는 검색 상태와 정규화된 도서 결과를 사용하며 Provider별 응답이나 오류
  유형은 화면에 전달되지 않는다.
- 현재 Provider가 반환하는 결과 전체를 한 목록에서 제공하며 별도의 페이지 이동이나 더
  보기 기능은 이번 범위에 포함하지 않는다.
- 검색어는 양끝 공백을 제거한 뒤 최대 200자로 제한하며, 별도의 허용 문자 제한은 두지
  않는다.
- 이 화면은 로그인한 사용자를 대상으로 하며 인증되지 않은 접근에는 기존 로그인 흐름을
  재사용한다.
- 결과 항목의 선택과 로컬 Book 등록, Reading 생성은 IMP-024에서 구현한다.
- 결과에서 Book Knowledge 상태를 표시하거나 준비 작업을 시작하는 기능은 이번 범위에
  포함하지 않는다.
- 실제 외부 검색 호출 없이 Normal, Loading, Empty, Error 및 정상 결과 화면을 자동으로
  검증할 수 있는 대체 검색 결과를 사용한다.
